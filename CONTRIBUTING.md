# Как участвовать в разработке «Пульса»

Спасибо за интерес к проекту! Мы рады баг-репортам, документации и коду.

## Кодекс поведения

Участвуя в проекте, вы соглашаетесь с [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

## Лицензия вклада

Проект распространяется по **AGPL-3.0-or-later**. Отправляя pull request, вы соглашаетесь
на распространение своего вклада под этой же лицензией (inbound = outbound, без отдельного CLA).

## Окружение

- Node.js ≥ 20, pnpm 11 (`corepack enable`)
- Docker с Compose для PostgreSQL 16 и Valkey 8

```bash
pnpm install
cp .env.example .env
pnpm docker:dev:up
pnpm db:migrate
```

## Перед отправкой PR

Прогоните локально ровно то, что проверяет CI:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm format:check
pnpm license:check
```

Если вы меняли схему Prisma — приложите миграцию (`pnpm db:migrate --name <что-изменилось>`).
Если меняли API — добавьте или обновите smoke-тест.

## Правила для кода

- **Лицензионный заголовок.** Каждый новый исходник начинается со строки
  `// SPDX-License-Identifier: AGPL-3.0-or-later` (в CSS — `/* ... */`).
- **Типы.** Строгий TypeScript; `any` — только с комментарием, объясняющим причину.
- **Общие схемы.** Валидация данных — Zod-схемы в `packages/shared`, не дублируйте их в приложениях.
- **Тесты.** Новая логика приходит с тестом. Багфикс — с тестом, который падал до фикса.
- **Доступность.** Интерфейс соответствует WCAG 2.1 AA: контраст, клавиатура, подписи для скринридеров.
- **Тексты интерфейса.** Без обвинений и давления: «Записал! Хорошего вечера», а не «Вы превысили бюджет».
- **Лицензии зависимостей.** Допустимы MIT, Apache-2.0, BSD, ISC, PostgreSQL, MPL-2.0, OFL-1.1.
  GPL/AGPL-совместимые — можно; проприетарные — нельзя. Проверяет `pnpm license:check`.

## Коммиты и PR

- Атомарные коммиты с внятным сообщением в императиве:
  `feat(api): добавлен эндпоинт /health`, `fix(web): тёмная тема не применялась к карточкам`.
- Один PR — одна тема. Описание: что изменилось, зачем, как проверить.
- Публичные профили, HTML-песочница, AI-помощник и всё, что касается чувствительных данных,
  требуют особенно внимательного ревью.
