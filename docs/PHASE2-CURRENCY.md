# Фаза 2 — мультивалютность с курсом на дату (ТЗ §3.2)

Реализация мультивалютности: у счёта своя валюта, у транзакции — валюта и
зафиксированный на дату операции курс к основной валюте пользователя. Итоги
статистики, бюджеты и дашборд считаются в основной валюте через `amount_base`.

## Данные (миграция `20261001155500_multicurrency`)

- `Account` — уже имел `currency` (RUB/USD/EUR); теперь полноценно используется.
- `Transaction` — новые поля:
  - `rate Decimal(18,8) @default(1)` — курс валюты операции к основной валюте
    пользователя, зафиксированный на дату операции;
  - `amount_base Decimal(14,2) @default(0)` — сумма в основной валюте
    (`amount × rate`);
  - `to_amount Decimal(14,2)?` — сумма зачисления при переводе между счетами
    разных валют.
- `ExchangeRate` — справочник курсов: `(user_id, date, base, quote)` уникальны,
  `rate Decimal(18,8)`, `source` = `manual` | `provider`.

Существующие строки мигрированы как `rate = 1`, `amount_base = amount`
(данные остаются в основной валюте, ничего не пересчитывается задним числом).

## Источник курсов: self-hosted по умолчанию

Обязательных облаков нет: курсы вводятся вручную через `/api/finance/rates`.
Опционально включается публичный источник без ключа (frankfurter.dev, данные
ECB) переменными окружения:

| Переменная | Значение | Назначение |
| --- | --- | --- |
| `RATES_PROVIDER` | пусто / `frankfurter` | `frankfurter` включает подтягивание курсов с публичного API |
| `RATES_API_URL` | по умолчанию `https://api.frankfurter.dev/v1` | своё зеркало (ECB-совместимое) |

Сетевой клиент (`FrankfurterRatesProvider`) спрятан за интерфейсом
`RatesProvider`; в Nest он подставляется фабрикой `createRatesProvider()`.
Если `RATES_PROVIDER` не задан — провайдер `null` и работают только ручные
курсы. В автотестах сетевых запросов нет: клиент проверяется с подменённым
`fetch`, а интеграционные тесты идут без `RATES_PROVIDER`.

Если ручного курса нет, а провайдер включён, недостающий курс подтягивается и
кешируется в `exchange_rates` (source = `provider`). Если курса нет нигде —
операция отклоняется с `400 rate_not_found`.

## Эндпоинты (префикс `/api/finance`, под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/rates?date&base&quote` | Курсы пользователя с фильтрами |
| PUT | `/rates` | Создать/обновить ручной курс `(date, base, quote)` |
| DELETE | `/rates/:id` | Удалить свой курс |

`Transaction` (`POST /transactions`) принимает `currency` (по умолчанию — валюта
счёта; иная валюта, чем у счёта, отклоняется с `currency_mismatch`) и
необязательный `rate`. `POST /transfers` принимает `toAmount` — сумму
зачисления в валюте счёта-получателя; без неё она считается по курсу на дату.

Новые коды ошибок: `rate_not_found`, `currency_mismatch`.

## Чистые функции (`packages/shared/src/currency.ts`)

- `pickRate(points, base, quote, date)` — ближайший курс на дату, иначе последний
  предыдущий; понимает обратную пару.
- `nearestRate(...)` — то же, числом.
- `crossRate(points, from, to, base, date)` — кросс-курс через основную валюту.
- `convertToBase(amount, rate)` — округление до копеек (Decimal(14,2));
  `roundRate` — округление курса до 8 знаков (Decimal(18,8)).

## Web

- Форма счёта: выбор валюты (RUB/USD/EUR).
- Шторка быстрого ввода: выбор валюты сужает список счетов до счетов этой валюты.
- Список транзакций: для операций в чужой валюте показан эквивалент в основной
  валюте (`≈ … в RUB`).
- Экран `/finance/rates` — CRUD ручных курсов.
- Все строки интерфейса — в `src/lib/i18n.ts` (ru/en, одинаковый набор ключей).

```bash
pnpm --filter @puls/shared test   # +17 тестов: currency.test.ts

```

Интеграционные тесты (`apps/api/test/currency.integration.test.ts`) проверяют:
ручной CRUD и изоляцию курсов по пользователю; фиксацию курса и `amount_base`
для USD-траты; попадание USD-траты в итоги статистики и бюджета в RUB по курсу
даты; отсутствие курса → `rate_not_found`; перевод USD→RUB двумя суммами и
возврат балансов при удалении.
