# Фаза 1.4 — статистика

Реализация ТЗ §3.4, §6 (кеширование агрегатов, доступность) и §8 (экран
«Статистика»): дневные агрегаты, дашборд дня, отчёты за период, тепловая карта
настроения и сравнение периодов.

## Эндпоинты (префикс `/api/stats`, все под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/day?date=YYYY-MM-DD` | Дашборд дня: траты, доходы, остаток бюджета, среднее настроение, чек-ины |
| GET | `/report?period=day\|week\|month\|year&date=YYYY-MM-DD` | Отчёт: траты по категориям, доходы против расходов, ряд по дням, сравнение с прошлым периодом |
| GET | `/mood-calendar?month=YYYY-MM` | Календарь-тепловая карта: среднее настроение по каждому дню месяца |

Без параметров `date` берётся текущий день в часовом поясе пользователя,
`period` по умолчанию — `month`. Ошибки в едином формате `{ code, message }`:
`validation_error` (некорректная дата, период или месяц), `unauthorized`.

## Модель данных (ТЗ §7)

- `DailyStat` — `user_id`, `date` (`@db.Date`), `spent`, `earned` (`Decimal(14,2)`),
  `avg_mood` (`Float?`), `checkins_count`, уникальность `(user_id, date)`.
- Миграция: `prisma/migrations/20261001125957_daily_stat`
  (`pnpm exec prisma migrate dev --name daily_stat`).

## Пересчёт и кеш агрегатов (ТЗ §6)

`StatsService.recomputeRange` пересчитывает дневные агрегаты лениво — при чтении
статистики, а не при записи транзакции. Это минимально-инвазивно: модуль финансов
и модуль чек-инов не меняются и не знают о статистике.

- В `DailyStat` попадают только дни с данными (траты, доходы или чек-ины) плюс
  сегодняшний день — дашборд готов к пустому дню.
- Запись — `upsert` по `(user_id, date)` в одной транзакции БД, поэтому кеш не
  расходится с данными: дашборд обновляется сразу после новой траты
  (`GET /stats/day` пересчитывает день перед ответом).
- Суммы не «списываются» из кеша и не дублируются: источник истины — таблицы
  `transactions` и `check_ins`, `DailyStat` — только кеш.

## Границы дней по часовому поясу (ТЗ §3.4, §6)

Границы дня считаются в часовом поясе пользователя (`users.timezone`):

- `dayKeyInTimezone(instant, tz)` — к какому дню относится момент (чек-ин в
  22:30 UTC — уже следующий день в Москве и ещё текущий в UTC);
- `zonedDayBounds(dayKey, tz)` — UTC-интервал `[начало, конец)` дня, с учётом
  перехода на летнее/зимнее время (день длиной 25 и 23 часа);
- `periodRangeFromDay(period, dayKey)` — неделя с понедельника по воскресенье,
  месяц и год — календарные.

Транзакции хранят дату как `@db.Date` (календарный день операции), поэтому их
день не сдвигается часовым поясом; пояс влияет на чек-ины (у них timestamp) и на
определение «сегодня».

## Агрегация (чистые функции в `@puls/shared`)

Вся математика — отдельные чистые функции `packages/shared/src/stats.ts` с
unit-тестами: `sumSpent` / `sumEarned` (переводы между счетами не расход),
`groupSpentByCategory` (по убыванию суммы), `budgetRemaining`, `buildMoodCalendar`,
`comparePeriods` (проценты через `percentChange`), `moodAverage`, `roundMoney`.

Отчёт за период дополнительно отдаёт ряд по дням (`series`) для графика и
`comparison` — процентная разница с предыдущим таким же периодом.

## Web (ТЗ §8, §6 — WCAG 2.1 AA)

- `/stats` — переключатель периода (день / неделя / месяц / год), итоги, сравнение
  периодов, столбчатый график трат, траты по категориям и тепловая карта
  настроения за месяц.
- Графики — простые SVG без тяжёлых библиотек (`lib/charts.ts`: раскладка
  столбцов, уровень тепловой карты, сводка ряда).
- Доступность: у каждого SVG `role="img"`, `<title>` и `<desc>` с текстовым
  описанием, у тепловой карты — скрытый список дней со значениями настроения;
  переключатель периода — `role="group"` с `aria-pressed`.
- Блок дашборда дня на `/app` (`components/today-stats.tsx`) слушает событие
  `puls:finance-changed` и обновляется сразу после быстрого ввода траты.
- Все строки — в `src/lib/i18n.ts` (ru/en), зашитых текстов нет.

## Изоляция и безопасность (ТЗ §6)

Каждый запрос фильтруется по `user_id` текущей сессии; чужой пользователь не
видит ни трат, ни настроения (тест «Изоляция данных»). Без сессии — `401`.
