# Фаза 1.1 — аутентификация и онбординг

Реализация ТЗ §3.1, §6 и §7 (v3): регистрация с начального экрана по логину и
паролю, серверные сессии, вход по логину **или** почте, сброс пароля по
одноразовой ссылке, ограничение частоты входов, CSRF и онбординг из 4 шагов.
Двухфакторная аутентификация и вход через Telegram удалены (см.
`docs/PHASE2-2FA.md`).

## Эндпоинты (префикс `/api`)

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| GET | `/auth/csrf` | — | Выдаёт CSRF-cookie `puls_csrf` (double-submit) |
| POST | `/auth/register` | +CSRF | Регистрация логин+пароль, почта необязательна; сессия сразу |
| GET | `/auth/nickname-available` | — | Живая проверка доступности логина на форме регистрации |
| POST | `/auth/login` | +CSRF | Вход по логину **или** почте, cookie `puls_session` |
| POST | `/auth/forgot-password` | +CSRF | Письмо со ссылкой сброса (если у пользователя есть почта и настроен SMTP) |
| GET | `/auth/password-token` | — | Что за токеном: `{ valid, purpose, nickname }` |
| POST | `/auth/reset-password` | +CSRF | Установка/сброс пароля по токену; завершает все сессии |
| POST | `/auth/verify-email` | +CSRF | Подтверждение почты по токену (необязательно, вход не блокирует) |
| POST | `/auth/verify-email/resend` | +CSRF | Повторное письмо (без раскрытия адресов) |
| GET | `/auth/me` | сессия | Текущий пользователь, статус онбординга, `needsEmail` |
| POST | `/auth/logout` | сессия | Завершение текущей сессии |
| GET | `/auth/sessions` | сессия | Список активных сессий (без хешей токенов) |
| DELETE | `/auth/sessions` | сессия | «Выйти из всех сессий»: завершает все входы, кроме текущего |
| DELETE | `/auth/sessions/:id` | сессия | Отзыв своей сессии |
| PUT | `/auth/onboarding` | сессия | Сохраняет 4 шага и создаёт первый счёт |
| GET | `/auth/dev/outbox` | dev | Письма из in-memory транспорта (для e2e) |

`login` в теле входа переиспользуется как для никнейма, так и для почты
(поле `email` из старых клиентов принимается как синоним).

Ошибки в едином формате `{ code, message }`: `email_taken`, `nickname_taken`,
`invalid_nickname`, `nickname_change_not_allowed`, `validation_error`,
`invalid_credentials`, `invalid_token`, `rate_limited`, `csrf_failed`,
`registration_closed`, `registration_invite_required`, `unauthorized`.

## Регистрация и вход (ТЗ §7)

- **Регистрация** — логин (никнейм), пароль и повтор пароля; почта
  необязательна. Сессия выдаётся сразу, письмо подтверждения (если почта указана)
  вход не блокирует. Формат логина: 3–32 символа, латиница, цифры, `-`/`_`,
  не занят и не зарезервирован.
- **Вход** — логин (никнейм) **или** почта плюс пароль.
- **2FA** — нет; **вход через Telegram** — нет (Telegram остаётся только
  каналом уведомлений и ботом).
- **Вход через Google** — остаётся (см. `docs/PHASE2-OAUTH.md`).

## Сброс и установка пароля (ТЗ §7)

- Пароль — **минимум 8 символов** (максимум 128).
- Ссылка одноразовая, срок жизни **30 минут**; в БД хранится только SHA-256
  (`password_tokens`), новые запросы гасят прежние неиспользованные токены.
- Ссылку выдаёт `POST /auth/forgot-password` (письмо, если у пользователя есть
  почта) либо команда `/password` в Telegram/Discord-боте. Email не обязателен.
- Токен имеет `purpose`: `reset` — у пользователя уже есть пароль; `setup` — пароля
  ещё нет (например, аккаунт из Telegram), тогда на той же странице можно задать
  и логин.
- Установка нового пароля **завершает все сессии** пользователя.
- Пользователям, входившим только через Telegram (`passwordHash = null`), бот при
  первом сообщении сам присылает setup-ссылку «задайте логин и пароль».

## Безопасность (ТЗ §6)

- Пароли — Argon2id (`argon2`), параметры OWASP, переопределяются `ARGON2_*`.
- В БД хранится только SHA-256 от токена сессии/письма/пароля; cookie httpOnly,
  `SameSite=Lax`, `Secure` в production.
- CSRF — глобальный guard для всех мутирующих запросов (`X-CSRF-Token` == cookie).
- Ограничение входов: **5 попыток на логин/почту и 100 на IP за 15 минут**
  (`Retry-After`). Хранилище — Valkey (ioredis) с автоматическим откатом на
  in-memory.
- «Выйти из всех сессий» — `DELETE /auth/sessions` завершает все входы, кроме
  текущего.

## Переменные окружения

`DATABASE_URL`, `REDIS_URL`, `CORS_ORIGIN`, `WEB_APP_URL` (ссылка в письме),
`MAIL_TRANSPORT=console|smtp`, `SMTP_URL`, `MAIL_FROM`, `SESSION_TTL_DAYS=30`,
`EMAIL_VERIFY_TTL_HOURS=24`, `RATE_LIMIT_STORE=memory` (для тестов), `API_INTERNAL_URL`
(адрес API для серверных запросов Next), `ARGON2_MEMORY_COST`/`ARGON2_TIME_COST`/`ARGON2_PARALLELISM`.
Срок жизни ссылки сброса пароля — константа в коде (30 минут), не переменная.

## Тесты

```bash
pnpm --filter @puls/shared test    # юнит-тесты схем
pnpm --filter @puls/api test       # юнит + интеграционные (схема puls_test)
pnpm --filter @puls/web test       # юнит-тесты
pnpm e2e                           # Playwright: регистрация → онбординг → кабинет
```

Ключевые файлы: `apps/api/test/auth.integration.test.ts` (регистрация без почты,
вход по логину и по почте, сброс/установка пароля, «выйти из всех сессий»,
лимиты), `external-auth.integration.test.ts` (вход через Telegram удалён).
Интеграционные тесты идут в отдельную схему `puls_test` той же БД
(`TEST_DATABASE_URL` переопределяет хост, схема задаётся принудительно).
