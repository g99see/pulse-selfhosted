# Фаза 1.2 — финансы

Реализация ТЗ §3.2, §5 (сценарий 1) и §7: категории, счета, транзакции за
несколько нажатий, быстрый ввод текстом, переводы и бюджеты на месяц.

## Эндпоинты (префикс `/api/finance`, все под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/overview?month=YYYY-MM` | Сводка для экрана: счета, категории, транзакции, бюджеты |
| GET | `/categories` | Системные + свои категории с иконкой и цветом |
| POST | `/categories` | Своя категория (иконка, цвет, тип) |
| PUT | `/categories/:id` | Правка своей категории |
| DELETE | `/categories/:id` | Удаление своей категории |
| GET | `/accounts` | Счета и общий баланс |
| POST | `/accounts` | Счёт типа `card` / `cash` / `savings` |
| PUT | `/accounts/:id` | Правка счёта |
| DELETE | `/accounts/:id` | Удаление счёта |
| GET | `/transactions?from&to&accountId&categoryId&type&limit` | Список с фильтрами |
| POST | `/transactions` | Доход или расход, дата по умолчанию — сегодня |
| POST | `/transactions/quick` | Быстрый ввод: «обед 450», «зарплата +80000» |
| DELETE | `/transactions/:id` | Удаление с возвратом баланса |
| POST | `/transfers` | Перевод между счетами (не расход) |
| GET | `/budgets?month=YYYY-MM` | Бюджеты с потраченным и уровнем |
| PUT | `/budgets` | Бюджет на месяц по категории |
| PUT | `/budgets/:id` | Правка лимита |
| DELETE | `/budgets/:id` | Удаление бюджета |

Ошибки в едином формате `{ code, message }`: `validation_error`,
`account_not_found`, `category_not_found`, `transaction_not_found`,
`budget_not_found`, `system_category`, `no_account`, `unauthorized`.

## Данные (ТЗ §7)

- `Category` — `user_id` = `NULL` для системных (засеяны миграцией: еда,
  транспорт, жильё, развлечения, здоровье, подписки, покупки, связь, прочее,
  зарплата, прочий доход), свои — с иконкой и цветом.
- `Account` — тип `card` / `cash` / `savings`, баланс `Decimal(14,2)`.
- `Transaction` — доход / расход / перевод (`transfer` + `transfer_account_id`),
  сумма `Decimal(14,2)`, дата (`date`), комментарий.
- `Budget` — уникальность `(user_id, category_id, month)`, лимит `Decimal(14,2)`.

Суммы хранятся как `Decimal`, в API отдаются числами. Баланс счёта меняется в
одной транзакции БД с записью транзакции; удаление/перевод баланс возвращают.
Переводы не попадают в расходы и не учитываются в бюджетах.

## Быстрый ввод и бюджеты

- `parseQuickTransaction` и `guessCategoryName` живут в `@puls/shared`: «обед 450»
  → категория «Еда», «зарплата +80000» → «Зарплата».
- Уровни бюджета (ТЗ §3.2): `ok` < 80%, `warning` ≥ 80%, `exceeded` ≥ 100%
  (`budgetLevel` перенесён в `@puls/shared`, web реэкспортирует из `lib/budget`).

## Web

- `/finance` — счета, список транзакций с фильтрами по типу/категории/счёту,
  бюджеты с прогресс-барами (ТЗ §8, экран «Финансы»).
- Кнопка «+» в каркасе открывает шторку быстрого добавления: строка ввода,
  категории, необязательный комментарий — сохранение за три нажатия.
- Все строки интерфейса — в `src/lib/i18n.ts` (ru/en).

## Изоляция и безопасность (ТЗ §6)

Каждый запрос фильтруется по `user_id` текущей сессии; чужой счёт, категория,
транзакция или бюджет не видны (`404`), системные категории не редактируются
(`403`). Это закреплено интеграционным тестом «Изоляция данных между
пользователями».

## Тесты

```bash
pnpm --filter @puls/shared test    # 51 юнит-тест (схемы и утилиты, из них 20 финансовых)
pnpm --filter @puls/api test       # 58 тестов (22 юнит + 36 интеграционных, схема puls_test)
pnpm --filter @puls/web test       # 48 юнит-тестов
pnpm e2e                           # Playwright: сценарий 1 — быстрый ввод «обед 450» → «Еда»
```

Интеграционные тесты сохраняют системные категории между прогонами (удаляют
только пользовательские), миграции накатываются в схему `puls_test`.
