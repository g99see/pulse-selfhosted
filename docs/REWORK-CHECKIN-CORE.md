# «Пульс»: чек-ин — ядро, финансы — вторичный модуль

**Тип:** продуктово-UX предложение по переработке. **Статус:** черновик к согласованию.
**Рамка:** самонаблюдение, не диагностика. Без баллов-вердиктов, без «у вас депрессия»,
красный для настроения не используется (ТЗ §3.5, §6, §8; палитра `MOOD_COLORS`).
Ничего в модуле финансов сейчас **не меняется** — он помечается `TODO: переделать`.
Опирается на: `docs/CHECKIN-IDEAS.md`, `docs/PHASE1-CHECKINS.md`, `docs/PHASE2-INSIGHTS.md`,
`packages/shared/src/{checkin,checkin-dialog,checkin-parser,correlations,insights}.ts`,
`apps/web/src/app/(app)/{app,checkin}/page.tsx`, `apps/web/src/components/{app-shell,checkin-card}.tsx`,
лендинг `apps/web/src/app/page.tsx`, ТЗ §1, §3.2–3.6, §4, §5.

## 1. Позиционирование и ядро цикла

**Сейчас** продукт симметричен: «деньги и самочувствие в одной ленте» (лендинг
`landing.title`, ТЗ §1). Это размывает фокус: два равноправных ядра не запоминаются.

**Предложение.** «Пульс» — **дневник самочувствия**, который замечает связи с деньгами.
Финансы — **необязательный модуль** рядом, а не второй вход в продукт. Позиционирование:

- RU: «Пульс — дневник самочувствия. Отметьте состояние за 5 секунд; деньги — рядом.»
- EN: "Puls — a wellbeing journal. Log how you feel in 5 seconds; money lives next door."

**Ядро цикла (единственный обязательный сценарий):**

> напоминание → **1 тап по шкале настроения** (≈5 сек) → мгновенный отклик →
> необязательное углубление (1–2 вопроса) → за неделю сервис показывает наблюдение →
> возвращает к следующему чек-ину.

Обоснование: у лидеров вход — 1–2 тапа («2 taps / five seconds» у Daylio
<https://daylio.net/>); Finch считает серию за сам факт открытия — «отметиться достаточно»
(<https://help.finchcare.com/hc/en-us/articles/37780736136205-Understanding-Streaks>);
Apple разводит «прямо сейчас» и «за день» (momentary vs daily mood)
(<https://developer.apple.com/videos/play/wwdc2024/10109/>).

## 2. Новый поток чек-ина

### 2.1 Ядро — 5 секунд, всегда

Один тап по шкале 1–5. Под эмодзи — **словесные анкеры** (сейчас у шкалы нет смысла словами):
«тяжело → так себе → нормально → хорошо → отлично». Полностью проанкеренные шкалы снижают
ошибку измерения (<https://www.imperial.ac.uk/education-research/evaluation/tools-and-resources-for-evaluation/questionnaires/developing-your-own-and-amending-existing-questionnaires/developing-items-and-their-response-options>).
**Текст-хелпер зависит от слота** (снижает ошибку воспоминания,
<https://journals.sagepub.com/doi/full/10.1177/25152459241267912>):

| Слот | RU | EN |
| --- | --- | --- |
| morning / day | «Как ты чувствуешь себя прямо сейчас?» | "How do you feel right now?" |
| evening | «Как прошёл день?» | "How was your day?" |

### 2.2 Вопросы по слотам — коротко

Сейчас в каждом слоте доступны `энергия, стресс, сон, вода, шаги, теги, заметка` (`details open`).
Это тяжёлая форма (<https://pmc.ncbi.nlm.nih.gov/articles/PMC11633767/>). Предлагаем:

| Слот | Всегда | Необязательно (1 доп.) | Убираем из слота |
| --- | --- | --- | --- |
| morning | настроение | сон (0–24 ч), энергия | вода, шаги |
| day | настроение | энергия | сон, вода, шаги |
| evening | настроение | итог дня «Что получилось?», стресс | сон, вода, шаги |

Воду/шаги не спрашиваем каждый слот — выносим в трекер привычек (`HabitsToday`, уже есть)
или один раз в день (идея 5 из `CHECKIN-IDEAS.md`). Расширенный блок — **закрыт по умолчанию**,
открывается по «＋ Углубить» (прогрессивное раскрытие, идея 3).

### 2.3 Адаптивные уточнения

При `mood ≤ 2` (или `energy ≤ 2`) под шкалой появляется строка **чипов-причин**: «работа»,
«ссора», «болею», «не выспался», «своё». Один тап, необязательно, можно пропустить.
Адаптивный вопрос «в момент» даёт контекст без удлинения формы
(<https://pmc.ncbi.nlm.nih.gov/articles/PMC11633767/>); называние состояния словами
(affect labeling) само по себе полезно — и выбор из готовых ярлыков уже считается
(<https://journals.sagepub.com/doi/10.1111/j.1467-9280.2007.01916.x>,
<https://doi.org/10.1177/1754073917742706>).

Дополнительно — **один необязательный тап**: метка состояния (напр. «устал», «тревожно»,
«спокойно», «рад») и/или тап энергии (valence‑arousal, измерение «энергия»
<https://pmc.ncbi.nlm.nih.gov/articles/PMC2367156/>). Обе метки — топливо для уже
существующего движка правил/корреляций, без нового UX.

## 3. Изменения модели данных (обратная совместимость)

**Принцип: только аддитивно, существующие строки `CheckIn` не трогаем.**

| Поле | Тип | Зачем | Совместимость |
| --- | --- | --- | --- |
| `reason` | `String?` | причина при `mood ≤ 2` (или пишем в `tags`) | nullable → старые строки `null` |
| `moodKind` | `String?` (`momentary`/`daily`) | отличать «прямо сейчас» и «за день» | nullable |
| `affect` | `String?` | выбранная метка состояния | nullable |
| `energy` | `Int?` (уже есть) | 2‑я ось valence‑arousal | используется как есть |

- Миграция — один `ALTER TABLE check_ins ADD COLUMN ... NULL` (Prisma `migrate`). Без перезаписи
  данных; `mood` остаётся обязательным.
- `water`, `steps` **не удаляем** — просто перестаём спрашивать каждый слот (данные и история целы).
- `CheckInInputSchema` (`packages/shared/src/checkin.ts`) расширяется **только опциональными**
  полями → API и web остаются совместимыми, старые клиенты и черновики Telegram продолжают работать.
- `CheckInDto` получает `| null`‑поля; UI читает `null` как «не указано».
- `checkin-dialog.ts`: шаг причины добавляется **условно** (только при низкой оценке), шаг `sleep`
  остаётся утром; старый черновик без `reason` штатно завершается через `finish()`.
- Новые константы в shared: `MOOD_ANCHORS` (RU/EN), `CHECKIN_REASON_SUGGESTIONS`.
  `CHECKIN_BACKDATE_HOURS = 24` не трогаем.
- «Сегодня»/стрик/история — по‑прежнему из существующих полей; `occurredAt` не меняется.

## 4. Петля обратной связи: что видно сразу после отправки

Сейчас после тапа — «Записал! Хорошего дня» и строка серии (`checkin.card.saved`,
`checkin.card.streak`), конфетти при достижении. Усиливаем отклик, не давя:

1. **Мгновенное подтверждение** тем же тапом: мягкая строка + галочка серии
   («12 дней подряд — здорово»). Это и есть награда (модель Finch «отметиться достаточно»).
2. **Мини‑контекст** одной строкой: «3‑й чек‑ин сегодня» или, если есть данные,
   наблюдение из правил: «в дни со спортом настроение выше» (`insights.ts`).
3. **Необязательное «Углубить»**: кнопка открывает 1–2 адаптивных вопроса из §2.3.
4. Никакого давления: пропуск/сокращение — норма, не «провал» (см. §8).

## 6. Стратегия уведомлений

- **Меньше, но своевременнее.** Вместо жёсткого «1–6 раз в день» — 2 якоря (утро/вечер) + не
  более 1 дневного; cap и подавление, если ответ уже был. Своевременные напоминания повышают
  отклик (<https://pmc.ncbi.nlm.nih.gov/articles/PMC8059357/>,
  <https://pmc.ncbi.nlm.nih.gov/articles/PMC6293241/>).
- Использовать уже готовое «умное время» (`typicalAnswerTime`, медиана ответов, `PHASE1-NOTIFICATIONS.md`)
  и тихие часы 22:00–08:00 как есть.
- Канал — Telegram/Discord через outbox (v2). Кнопки настроения из напоминания сохраняем.
- Тексты напоминаний — wellbeing‑first («Как ты сейчас?»), деньги не пушим.

| --- | --- | --- | --- |

| 1 | Чипы‑причины при низкой оценке; `reason`/`moodKind`/`affect` (миграция аддитивно); строка‑отклик на главной; nav/home/settings/landing + маркер `TODO` | **M** | Слом e2e навигации; тон |

навигационные e2e — обновить `data-testid`; (4) переутомление от напоминаний — cap и подавление.

## 8. Чего НЕ делать

- Не вводить скрининги со скорингом: **PHQ‑2/PHQ‑9/WHO‑5** — мединструменты с порогом, в продукте
  им места нет (ТЗ §3.5, §6). Максимум — нейтральная формулировка без балла.
- Не делать «плохой день» визуальной ошибкой: красный, «зона риска», тревожные иконки — запрещено тоном.
- Не удлинять один чек‑ин; не спрашивать воду/шаги/сон в каждом слоте.
- Не удалять и не скрывать финансы — только **понизить** и помечать `TODO: переделать`; данные и история целы.
- Не отправлять аудио/заметки на сервер (распознавание — в браузере, `PHASE5-VOICE-CHECKIN`).
- Не снижать пороги корреляций и не подавать их как причинность (`correlations.ts`).
- Не превращать серию чек‑инов в давление.
- Не расширять окно задним числом за 24 ч.

## Топ‑5 улучшений по влиянию

1. **1 тап → мгновенный отклик** (серия + мини‑контекст): закрывает ядро цикла.
2. **Анкеры шкалы + хелпер «прямо сейчас / за день»**: дешёво, улучшает качество данных.
3. **Прогрессивное раскрытие**: закрытый «Углубить», ≤ 2 вопросов, снять воду/шаги из слотов.
4. **Одна метка состояния + чипы‑причины при низкой оценке**: сигнал для правил/корреляций.
5. **Smart‑напоминания с cap** вместо жёсткого 1–6/день.
