## Дефекты

### D1. Часы сна тихо теряются при расхождении таймзоны устройства и профиля — Medium
- **Шаги:** профиль с tz `Europe/Berlin`; браузер с `timezoneId=America/New_York` (локально 11:55 → «утро»); открыть `/checkin`; поле «Часы сна» показано; ввести `7.5`; выбрать настроение; «Сохранить чек-ин».
- **Ожидалось:** `sleepHours = 7.5` в сохранённом чек-ине.
- **Фактически:** `sleepHours = null`. В истории «Утро 16 окт., 11:55» — значения сна нет.
- **Причина:** клиент показывает поле по **таймзоне устройства** (`Intl...timeZone`, `page.tsx:72`), а сервер сохраняет `sleepHours` по **таймзоне профиля** (`checkins.service.ts:88,96` и `checkin-dialog.service.ts:145`). При расхождении значение молча отбрасывается.
- **Control:** профиль и устройство оба `America/New_York` → `sleepHours = 7.5` сохраняется. Значит баг именно в расхождении источников времени.
- **Evidence:** скриншоты `bug-sleep-filled.png` (поле заполнено), `bug-sleep-history-after-save.png` (в истории сна нет); вывод `scripts/tz-repro.js`.
- **Влияние:** пользователи в поездке / с устаревшей tz профиля теряют данные без предупреждения.

### D2. При недоступном API перезагрузка даёт сырую страницу «Application error» — Medium
- **Шаги:** остановить API (`systemctl --user stop puls-api.service`); перезагрузить `/checkin`.
- **Ожидалось:** понятный экран ошибки/повтор/редирект на `/login` с сообщением.
- **Фактически:** `Application error: a server-side exception has occurred while loading localhost ... Digest: 3227098399` (страница 500 Next.js), плюс PAGEERROR в консоли.
- **Причина:** в `(app)/layout.tsx` `await fetch(.../auth/me)` без try/catch: при недоступности API запрос падает и роняет рендер.
- **Evidence:** `err-1b-reload-api-down.png`.
- **Замечание:** при живом API и падении запроса на **submit** ошибка обрабатывается корректно — «Что-то пошло не так. Попробуйте ещё раз.» (`err-1-submit-api-down.png`).

### D3. Ошибка «нет настроения» вне экрана — Medium
- **Шаги:** iPhone 14, `/checkin`; проскроллить к кнопке «Сохранить чек-ин»; не выбирая настроение, нажать «Сохранить».
- **Ожидалось:** сообщение «Сначала выберите настроение.» видно рядом с действием (или фокус/скролл к ошибке).
- **Фактически:** сообщение рендерится в начале страницы (role=alert), `boundingBox.y = -678` при высоте вьюпорта 664 → пользователь его не видит, кнопка «ничего не делает».
- **Evidence:** `val-1-nomood-at-save.png` (сообщения на экране нет). Скрипт `validate.js` п.1.

### D4. Нет UI заполнения задним числом (24 ч) — Medium
- **Ожидалось (ТЗ §3.3 / PHASE1-CHECKINS):** «Задним числом — окно 24 часа от occurredAt».
- **Фактически:** в UI нет ни поля даты/времени, ни упоминания; API поддерживает `occurredAt`, но из интерфейса недоступно. Список input/textarea на `/checkin`: water, steps, note, day-summary, goal, select, 3×time — даты нет.
- **Evidence:** `validate.js` п.6 (`hasDateInput=false`, `mentionsBackdate=false`).

### Мелкие
- **D5. Нет индикатора загрузки списка чек-инов** — при задержке `/api/checkins?*` секция «Мои чек-ины» пуста без скелетона/спиннера/`aria-busy` (проверено `validate.js` п.4). Low.
- **D6. Сообщение «Записал!» не сбрасывается** — остаётся после смены настроения (проверено: visible true → true). Low.
- **D7. Типографика < 16px** — массово: подписи полей 14px, подсказки/легенды/навигация 12px (38 узлов на мобильном, 40 на desktop). Базовый текст 16px. Low.
- **D8. ARIA-паттерн radiogroup не реализован** — у шкалы настроения `role=radio`, но нет roving tabindex и стрелок: ArrowRight не двигает выбор, все 5 кнопок в табуляции. На главной та же шкала — это действие (мгновенная запись), а не выбор, т.е. роль radio семантически неверна. Low.
- **D9. Ссылка-логотип «Пульс» в сайдбаре desktop — 224×34 (< 44 по высоте).** Остальные тап-таргеты ≥44. Low.
- **D10. Reload посреди формы теряет ввод** — заметка/шаги очищаются, черновик не сохраняется. Информационно.

## Проверено и работает
- **Скорость записи настроения:** главная = **1 тап, 174 мс**, 1 POST `/checkins/quick`; `/checkin` = 2 тапа (настроение + Сохранить), 123 мс. Цель ≤3 тапа/<5 с — выполнена. `flow-A-home-saved.png`, `flow-B-checkin-saved.png`.
- **Сон только 04:00–12:00** (tz Berlin): 03:59 нет, 07:00 есть, 11:59 есть, 12:00 нет, 13:00 нет, 21:00 нет — все верно (`slots-*.png`).
- **Слоты:** 07:00→`morning`, 21:00→`evening` подтверждено в БД (`горнинг/вечер` в истории).
- **Двойной тап по «Сохранить»:** 1 POST, +1 запись истории (кнопка блокируется на время busy).
- **Keyboard-only:** настроение и сохранение достигаются Tab+Space/Enter, чек-ин сохраняется.
- **Фокус-порядок:** skip-link → header → шкала настроения → «Расширенный чек-ин» → поля → сохранение. Логичен.
- **Тап-таргеты ≥ 44px** на всех устройствах (кроме D9).
- **Оверфлоу:** отсутствует на 320/390/412/1440, в RU и EN, с длинной заметкой и длинным итогом.
- **Тёмная тема:** применяется (`.dark`), контраст текста — 0 провалов WCAG AA (`dark-checkin.png`).
- **RU/EN:** сырых i18n-ключей и смешивания языков нет; теги переводятся (`work/sport`), `html lang` корректен.
- **Ошибки/оффлайн:** при падении API на submit и в офлайне — дружелюбное сообщение; после перезапуска API сохранение восстанавливается. Консольных ошибок в обычных флоуах нет.
- **Назад после submit:** уходит на `/app`, повторной отправки нет.

## Замечания по стенду (не дефекты UI)
- `puls-web.service` был запущен до пересборки (с 12 окт) и отдавал старую сборку — статика 400, JS не грузился, форма логина уходила нативным GET (пароль в query). **Исправлено:** `systemctl --user restart puls-web.service`.
- Документированная команда `scripts/dev-run.sh stop api` **не останавливает** реально работающий API: pid-файл `~/.local/state/puls/api.pid` устарел (dead pid), API управляется `puls-api.service`. Остановку/старт делал через systemctl.
- По завершении API и web перезапущены, `health=200`, `active`.
