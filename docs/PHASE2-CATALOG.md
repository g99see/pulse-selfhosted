# Фаза 2 — каталог категорий и магазинов (ТЗ v2 §8, §9)

Категории и автоопределение магазинов в выписках: расширенное дерево категорий,
свои категории с объединением, справочник мировых магазинов из файла данных,
сопоставление при импорте и очередь «Требует внимания».

## Категории (ТЗ v2 §8)

### Дерево

Источник истины — `packages/shared/src/categories.ts` (`STANDARD_CATEGORIES`):
**30 верхних категорий и 33 подкатегории** (63 всего), расходные и доходные.
У каждой: стабильный `key` (не меняется между версиями и языками), стабильный
`id` строки в БД (`sys-*`), необязательный `parent` (ключ родителя), названия
`name`/`nameEn`, иконка, цвет и набор `aliases` (для поиска по тексту).

Подкатегории, например: «Транспорт → Общественный транспорт / Бензин /
Парковка / Авто», «Жильё → Аренда / Дом и ремонт», «Путешествия → Авиабилеты /
Жильё в поездках / Междугородний транспорт», «Подписки → Музыка и видео /
Сервисы и софт».

Вспомогательные функции: `standardCategory(key)`, `standardCategoryId(key)`,
`standardCategoryCounts()`, `matchCategoryByText(text, categories, kind)` (поиск
по алиасам для быстрого ввода) и `orderCategoryTree(categories)` (плоский список
с `depth`, дети сразу под родителем).

### Модель БД

`categories` расширена колонками `key` (уникальный, у своих — `NULL`) и
`parent_id` (внешний ключ на `categories.id`, `ON DELETE SET NULL`).
Стандартные категории общие для всех (`user_id = NULL`): новые ключи выдаются
всем автоматически, без дублей строк на каждого пользователя.

### Миграция без потери истории

`apps/api/prisma/migrations/20261007130000_catalog/migration.sql`: добавляет
колонки и таблицу `user_merchants`, затем идемпотентно засеивает весь набор по
стабильному `id` (`ON CONFLICT ("id") DO UPDATE`). Прежние системные строки
(`sys-food`, `sys-transport`, `sys-housing`, …) сохраняют свои id, поэтому
транзакции, бюджеты и повторяющиеся платежи не теряют категорию — миграция лишь
дополняет строку ключом и родителем. Старые категории сопоставлены с новыми:

| Старое (id) | Новое (key) |
|---|---|
| `sys-food` | `food` (Еда) |
| `sys-transport` | `transport` (Транспорт) |
| `sys-housing` | `housing` (Жильё) |
| `sys-entertainment` | `entertainment` (Развлечения) |
| `sys-health` | `health` (Здоровье) |
| `sys-subscriptions` | `subscriptions` (Подписки) |
| `sys-shopping` | `shopping` (Покупки) |
| `sys-connectivity` | `connectivity` (Связь и интернет) |
| `sys-other` | `other` (Прочее) |
| `sys-salary` | `salary` (Зарплата) |
| `sys-other-income` | `other_income` (Прочий доход) |

### Переводы между своими счетами

Перевод — отдельный тип операции (`transactions.type = 'transfer'`,
`transfer_account_id`), а не расход: он не попадает в статистику трат и бюджеты.
Категория «Переводы» (`transfers`) — для переводов контрагентам (MobilePay,
Swish, Vipps), которые в выписке выглядят как списание.

### Свои категории

Создание, переименование, цвет, иконка, родитель (подкатегория), объединение и
удаление (`CategoriesService` в `apps/api/src/finance/categories.service.ts`).
Объединение (`POST /api/finance/categories/:id/merge { targetId }`) переносит
транзакции, бюджеты (с устранением коллизий уникального `(user_id, category_id,
month)`), повторяющиеся платежи и личные магазины на целевую категорию, а
исходную удаляет. Системные категории только для чтения (403 на изменение).

## Справочник магазинов и автоопределение (ТЗ v2 §9)

### База мировых магазинов

`apps/api/data/merchants.json` — файл данных, **696 записей** (регионы: Europe,
Nordics, North America, Global). Поля записи: `id`, `name` (каноническое
название), `aliases` (варианты написания), `patterns` (регулярные выражения,
146 записей), `defaultCategory` (ключ стандартной категории), `country`,
`region`. Файл включён ассетом Nest (`apps/api/nest-cli.json` →
`data/**/*` копируется в `dist/data`) и обновляется без изменения кода:
`MerchantsService` грузит его один раз и кеширует (`MERCHANTS_FILE` переопределяет
путь).

### Нормализация строки выписки

`packages/shared/src/merchants.ts` (`normalizeMerchantText`): приведение к
нижнему регистру, раскрытие диакритики (`ø→o`, `æ→ae`, `ё→е`, украинские
буквы), удаление лишних символов, кодов терминалов (`POS`, `TERM`, `BUTIK`,
`AVD`, `KORTKJØP`, …), городов, номеров точек, времени и дат. Отдельно
`merchantPatternText` сохраняет цифры — для проверки шаблонов.

### Порядок сопоставления

1. **Точное совпадение по алиасу** (фраза целиком в токенах описания),
2. **по шаблону** (регулярное выражение из `patterns`),
3. **нечёткое (fuzzy)** — максимум из коэффициента Дайса по биграммам и
   нормализованного расстояния Левенштейна, порог `MERCHANT_FUZZY_THRESHOLD = 0.84`.

**Личные магазины пользователя приоритетнее общей базы**:
`matchMerchantWithPriority(description, own, world)`.

### Сопоставление при импорте

При импорте выписки (`ImportService`) сначала ищется магазин (свои → общая
база), затем — категория по алиасам дерева (для родовых трат без магазина).
Операция получает магазин и категорию по умолчанию; нераспознанные операции без
категории попадают в очередь **«Требует внимания»**.

### Ручное добавление магазина

`POST /api/finance/stores` — название, категория, необязательный шаблон строки и
флаг `applyToSimilar`. При `applyToSimilar = true` категория проставляется всем
похожим операциям **без категории** — прошлым (прошлые выписки); будущие
распознаются автоматически при следующей загрузке, так как своя база
приоритетнее. Личные магазины: `GET /api/finance/stores`,
`PUT`/`DELETE /api/finance/stores/:id`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/finance/categories` | дерево категорий (системные + свои) |
| POST | `/api/finance/categories` | своя категория (может быть подкатегорией) |
| PUT | `/api/finance/categories/:id` | переименование, цвет, иконка, родитель |
| DELETE | `/api/finance/categories/:id` | удаление своей категории |
| POST | `/api/finance/categories/:id/merge` | объединение с целевой |
| GET | `/api/finance/merchants?q=` | поиск в общей базе магазинов |
| GET | `/api/finance/stores` | личные магазины |
| POST | `/api/finance/stores` | добавить магазин (+ apply to similar) |
| PUT | `/api/finance/stores/:id` | изменить магазин |
| DELETE | `/api/finance/stores/:id` | удалить магазин |
| GET | `/api/finance/unmatched?limit=` | очередь «Требует внимания» |

## Web (`apps/web`)

- `src/components/category-select.tsx` — выпадающий список дерева категорий
  (подкатегории с отступом, фильтр по типу).
- `src/components/category-manager.tsx` — свои категории: родитель,
  переименование, иконка, цвет, объединение, удаление.
- `src/components/store-dialog.tsx` / `store-manager.tsx` — добавить/изменить
  магазин, список личных магазинов.
- `src/app/(app)/finance/import/page.tsx` — очередь «Требует внимания» с кнопкой
  «Добавить магазин», магазин и категория в предпросмотре.
- `src/lib/finance-client.ts` — методы API каталога.
- Все тексты — в `src/lib/i18n.ts` (`finance.categories.*`, `finance.stores.*`,
  `finance.unmatched.*`, `finance.import.merchant*`, ru + en).
