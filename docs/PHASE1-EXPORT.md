# Фаза 1.7 — экспорт данных и удаление аккаунта

Реализация ТЗ §3.1 («Удаление аккаунта и экспорт всех данных (JSON и CSV) из
настроек»), §6 (приватность и безопасность) и критерия приёмки §9 «экспорт и
полное удаление данных работают из настроек».

## Эндпоинты (префикс `/api/account`, под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/account/export?format=json` | Единый JSON-документ со всеми данными пользователя |
| GET | `/api/account/export?format=csv` | ZIP-архив с CSV по сущностям |
| DELETE | `/api/account` | Полное удаление аккаунта с подтверждением |

Обе выгрузки и удаление работают только с данными текущей сессии. `DELETE`
дополнительно защищён глобальным `CsrfGuard` (double-submit cookie), как и все
мутирующие запросы (ТЗ §6).

### Формат JSON

```json
{
  "format": "puls.export",
  "version": 1,
  "generatedAt": "2026-10-01T13:20:00.000Z",
  "user": { "email": "…", "nickname": "…" },
  "counts": { "transactions": 1 },
  "data": { "accounts": [], "categories": [], "transactions": [], "budgets": [], "checkIns": [], "notificationRules": [], "dailyStats": [] }
}
```

Версия формата — константа `EXPORT_FORMAT_VERSION` в `@puls/shared`; растёт при
несовместимом изменении структуры документа.

### Формат CSV

ZIP-архив (метод STORE, собственный писатель `src/account/zip.ts` — без внешних
зависимостей) с файлами `users.csv`, `accounts.csv`, `categories.csv`,
`transactions.csv`, `budgets.csv`, `check_ins.csv`, `notification_rules.csv`,
`daily_stats.csv`. Заголовки стабильны: колонки берутся из
`information_schema.columns` в порядке объявления.

- Экранирование по RFC 4180: кавычки, запятые, `\r\n`; разделитель строк CRLF.
- Защита от инъекции формул (ТЗ §6): текстовые значения, начинающиеся с `=`,
  `+`, `-`, `@`, таба или CR, получают ведущую одинарную кавычку. Числа и даты,
  сгенерированные сервером, не портятся (отрицательная сумма остаётся числом).

### Заголовки ответа

`Content-Disposition: attachment; filename="puls-export-<никнейм>-<ГГГГ-ММ-ДД>.json|.zip"`
(плюс RFC 5987-вариант), `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.

## Реестр таблиц

`src/account/data-registry.ts` — единственное место, где перечислено, что входит
в выгрузку:

- `EXPORT_TABLES` — `users` (по `id`) и таблицы по `user_id`;
- `EXCLUDED_USER_TABLES` — с причиной: `sessions`,
  `email_verification_tokens`, `push_subscriptions` (секреты: хеши токенов,
  endpoint и ключи шифрования web push);
- `isSecretColumn()` отсекает колонки `password_hash`, `token_hash`, `*secret`,
  `auth`, `p256dh`, `private_key` в любой таблице.

Колонки выбираются динамически (из `information_schema`), поэтому новая
таблица выгружается без правки кода — достаточно добавить её в реестр.
Интеграционный тест «каждая таблица с `user_id` покрыта» падает, пока новая
таблица не внесена в выгрузку или в явные исключения.

## Удаление аккаунта

- Подтверждение: пароль (проверка через Argon2) и собственный никнейм.
  Коды ошибок: `confirmation_mismatch` (400), `invalid_password` (403),
  `rate_limited` (429), `unauthorized` (401).
- Удаление идёт в одной транзакции по всем таблицам с `user_id`
  (обнаруживаются в `information_schema`, поэтому каскад полный даже при
  отстающем реестре выгрузки) и затем по `users`.
- Сессии удаляются вместе с пользователем, cookie `puls_session` и `puls_csrf`
  сбрасываются, `204 No Content`.
- Журнал: `Logger` пишет строку без персональных данных — только необратимый
  хеш идентификатора, число таблиц и строк, IP.
- Защита от повторов: лимит попыток (5 за 15 минут) и идемпотентная транзакция;
  повторный вызов после успеха не проходит аутентификацию (401).

## Ограничение частоты (ТЗ §6)

- Экспорт: 5 выгрузок за 15 минут на пользователя (`429 rate_limited`).
- Удаление: 5 попыток за 15 минут. Лимитер — `RateLimitService` (Valkey или
  in-memory).

## Web

- `/settings` — страница настроек; секция «Данные и приватность» вынесена в
  отдельный компонент `src/components/data-privacy-section.tsx` и подключена
  одной строкой.
- Кнопки «Экспорт JSON» и «Экспорт CSV» скачивают файл, не уводя со страницы
  (blob + `Content-Disposition`).
- Удаление — модальное окно с вводом пароля и никнейма; после успеха переход на
  `/login`.
- Строки интерфейса — в `src/lib/i18n.ts` (ru/en).

## Тесты

```bash
pnpm --filter @puls/shared test   # 121 тест (в т.ч. 6 по схемам аккаунта)
pnpm --filter @puls/api test      # 167 тестов (в т.ч. 20 unit + 12 интеграционных по аккаунту)
pnpm --filter @puls/web test      # 76 тестов (в т.ч. 4 по клиенту выгрузки)
pnpm e2e                          # Playwright: export JSON/CSV и удаление из /settings
```

Интеграционные тесты проверяют: JSON-документ без секретов, ZIP с CSV и
нейтрализацию формул, изоляцию данных между пользователями, лимит выгрузок,
отказ по CSRF/паролю/подтверждению, а после удаления — ноль строк по `user_id`
во всех таблицах схемы и целостность данных второго пользователя.
