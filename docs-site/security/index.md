# Безопасность

«Пульс» хранит чувствительные данные — финансы и сведения о здоровье. Эта
страница описывает защитные механизмы сервиса.

Основана на `SECURITY.md`, `docs/PHASE1-AUTH.md` и
ТЗ §6.

## Транспорт: HTTPS и HSTS

Весь трафик идёт через Caddy, который автоматически получает сертификаты
Let's Encrypt для домена (`DOMAIN`) и отдаёт всё по HTTPS с HSTS.

## Аутентификация

- **Argon2** — хеширование паролей.
- **Cookie-сессии** — серверные; cookie `puls_session` помечена `httpOnly`.
- **CSRF** — токен `puls_csrf` обязателен для всех мутирующих запросов; клиент
  отправляет его заголовком `X-CSRF-Token` (через `authFetch`). При `csrf_failed`
  токен один раз обновляется и запрос повторяется.
- **Rate-limit** — ограничение частоты на вход и API; лимиты на попытки входа.
- **Вход по логину и паролю** — без 2FA и без входа через Telegram; сброс пароля через одноразовую ссылку от бота, после сброса все сессии отзываются.
- **Журнал входов и активных сессий.**

## Шифрование секретов: AES-256-GCM

Чувствительные поля шифруются на уровне приложения ключом `APP_ENCRYPTION_KEY`
(ровно 32 байта в base64). Формат — `v1.<iv>.<tag>.<ciphertext>` (случайный IV
12 байт, аутентификация GCM). Этим же механизмом (`SecretBoxService`,
`apps/api/src/crypto/`) будут шифроваться ключи AI-провайдеров.


## Роли

- **Роли** — пользователь / админ (`RolesGuard`, `@Roles`): админ видит метрики и настройки AI экземпляра.
- Данные одного пользователя другому не показываются: в приложении нет публичных профилей, ленты и общих разделов. Единственная внешняя ссылка — приватная ссылка «Итог дня» с секретным токеном, которую владелец может отозвать.

## Приватность и закон (ТЗ §6)

- Данные о здоровье и финансах — **чувствительные**. При self-hosted они хранятся
  только на сервере владельца экземпляра.
- За соблюдение законов (например, GDPR, где данные о здоровье — особая категория)
  отвечает тот, кто запускает экземпляр для других людей.
- Проект даёт инструменты: **экспорт и удаление данных**, экран согласия, журнал
  доступа администратора. Любая таблица с `user_id` учтена в реестре
  `account/data-registry.ts` — иначе экспорт/удаление её бы пропустили.

## Модель AI-приватности

> Кратко; подробности — на странице [AI-помощник](/ai/).

AI-провайдеру уходят только данные, нужные для ответа, без имени и email;
API-ключи хранятся зашифрованными и не попадают в логи.

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Используйте GitHub Security Advisories
(вкладка **Security → Report a vulnerability**) или закрытый email мейнтейнера.
Обещанные сроки реакции и область ответственности описаны в `SECURITY.md`.
