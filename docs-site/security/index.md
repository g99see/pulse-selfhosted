# Безопасность и песочница

«Пульс» хранит чувствительные данные — финансы и сведения о здоровье. Эта
страница описывает защитные механизмы сервиса и изоляцию пользовательского HTML.

Основана на `SECURITY.md`, `docs/PHASE2-2FA.md`, `docs/PHASE3-HTMLPAGE.md` и
ТЗ §6.

## Транспорт: HTTPS и HSTS

Весь трафик идёт через Caddy, который автоматически получает сертификаты
Let's Encrypt для основного домена (`DOMAIN`) и поддомена песочницы
(`SANDBOX_DOMAIN`) и отдаёт всё по HTTPS с HSTS.

## Аутентификация

- **Argon2** — хеширование паролей.
- **Cookie-сессии** — серверные; cookie `puls_session` помечена `httpOnly`.
- **CSRF** — токен `puls_csrf` обязателен для всех мутирующих запросов; клиент
  отправляет его заголовком `X-CSRF-Token` (через `authFetch`). При `csrf_failed`
  токен один раз обновляется и запрос повторяется.
- **Rate-limit** — ограничение частоты на вход и API; отдельные лимиты на второй
  фактор.
- **2FA TOTP** — по RFC 6238 (HMAC-SHA1, шаг 30 с, 6 цифр, окно ±1). Секрет
  хранится зашифрованным, резервные коды — только хешами (SHA-256); между паролем
  и кодом выдаётся одноразовый пропуск с TTL 5 минут. Повтор кода в окне
  отклоняется.
- **Журнал входов и активных сессий.**

## Шифрование секретов: AES-256-GCM

Чувствительные поля шифруются на уровне приложения ключом `APP_ENCRYPTION_KEY`
(ровно 32 байта в base64). Формат — `v1.<iv>.<tag>.<ciphertext>` (случайный IV
12 байт, аутентификация GCM). Этим же механизмом (`SecretBoxService`,
`apps/api/src/crypto/`) будут шифроваться ключи AI-провайдеров.

Поведение без ключа в production: 2FA **недоступна** — `POST /api/auth/2fa/setup`
отвечает `503 two_factor_unavailable`, `GET /api/auth/2fa` возвращает
`available: false`. Никакого «тихого» перехода на небезопасный ключ нет.

## Роли и приватность

- **Роли** — пользователь / модератор / админ (`RolesGuard`, `canModerate`).
  Модерация описана на странице [Администрирование](/admin/).
- **Приватность карточек и профиля** — видимость определяется в
  `shared/profile.ts` (`canViewProfile`, `canViewCard`); карточка со
  значением `private` не отдаётся никому, кроме владельца.

## Песочница пользовательского HTML (ТЗ §3.8)

Пользовательский HTML никогда не отдаётся с основного домена.

- Отдельный домен `SANDBOX_DOMAIN`; публичный маршрут — только `/sandbox/*`
  (`GET /sandbox/:nickname`).
- **Caddy срезает cookie в обе стороны** (`-Cookie`, `-Set-Cookie`): cookie
  основного сайта в песочницу не попадают и ею не выставляются.
- **Строгий CSP** на отдачу:

  ```
  Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline';
    style-src 'unsafe-inline' https:; img-src https: data:;
    form-action 'none'; base-uri 'none'; frame-ancestors <основной домен>
  X-Content-Type-Options: nosniff
  Referrer-Policy: no-referrer
  Cache-Control: no-store
  ```

- Показ на основном сайте — `iframe` с `sandbox="allow-scripts"` **без**
  `allow-same-origin` и с `referrerPolicy="no-referrer"`: у страницы чужой origin,
  cookie и данные сайта ей недоступны. Никогда не добавляйте `allow-same-origin`
  или `allow-top-navigation` и не ослабляйте CSP.

Перед публикацией HTML проходит автопроверку `checkHtmlPage` (`@puls/shared`):
статус `ok | blocked | flagged`. Заблокированная страница не публикуется.
Опционально подключается антивирус ClamAV (`CLAMAV_HOST`; пусто — проверка
выключена). Хранятся последние 10 версий, откат создаёт новую версию.

## Приватность и закон (ТЗ §6)

- Данные о здоровье и финансах — **чувствительные**. При self-hosted они хранятся
  только на сервере владельца экземпляра.
- За соблюдение законов (например, GDPR, где данные о здоровье — особая категория)
  отвечает тот, кто запускает экземпляр для других людей.
- Проект даёт инструменты: **экспорт и удаление данных**, экран согласия, журнал
  доступа администратора. Любая таблица с `user_id` учтена в реестре
  `account/data-registry.ts` — иначе экспорт/удаление её бы пропустили.

## Модель AI-приватности

> Кратко; подробности — на странице [AI-помощник](/ai/).

AI-провайдеру уходят только данные, нужные для ответа, без имени и email;
API-ключи хранятся зашифрованными и не попадают в логи.

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Используйте GitHub Security Advisories
(вкладка **Security → Report a vulnerability**) или закрытый email мейнтейнера.
Обещанные сроки реакции и область ответственности описаны в `SECURITY.md`.
