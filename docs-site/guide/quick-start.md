# Пошаговая установка (для новичков)

Эта страница для тех, кто ни разу не поднимал свой сервер. Ничего знать заранее не нужно.
Каждый шаг: что сделать, что напечатать и что вы должны увидеть. Если увидели не то, загляните
в раздел [«Что-то пошло не так»](#что-то-пошло-не-так).

::: tip Как читать команды
Всё, что в серых блоках, нужно **скопировать целиком и вставить** в чёрное окно терминала,
затем нажать **Enter**. Строки, начинающиеся с `#`, — пояснения, их можно не копировать.
:::

## Что понадобится

- **Компьютер-сервер**, который будет работать постоянно: старый ноутбук, мини-ПК,
  виртуальная машина или аренда VPS (от 4 € в месяц).
  Нужно минимум **2 ГБ памяти** (лучше 4) и **10 ГБ свободного места**.
- На нём система **Debian 12/13** или **Ubuntu 22.04/24.04**.
- Доступ к нему по SSH (или прямо клавиатура и экран).
- 15–20 минут. Первая сборка сама идёт около 10 минут, пока можно пить чай.

::: details У меня Proxmox
Создайте LXC-контейнер из шаблона Debian 13: 2–4 ядра, 4 ГБ памяти, диск 20 ГБ, статический IP.
**Обязательно** поставьте галочки **nesting** и **keyctl** (вкладка «Options → Features»),
иначе Docker внутри не запустится. Дальше всё как ниже.
:::

## Шаг 1. Зайдите на сервер

На своём компьютере откройте терминал:

- **Windows**: нажмите `Win`, наберите `PowerShell`, Enter.
- **macOS**: `Cmd + Пробел`, наберите `Терминал`, Enter.
- **Linux**: `Ctrl + Alt + T`.

Подключитесь (вместо `192.168.1.50` — адрес вашего сервера, вместо `root` — ваш логин на нём):

```bash
ssh root@192.168.1.50
```

Первый раз спросит `Are you sure you want to continue connecting?` — напишите `yes` и Enter.
Потом введите пароль от сервера (при вводе символы **не показываются**, это нормально).

✅ Вы на месте, если строка приглашения поменялась на что-то вроде `root@server:~#`.

## Шаг 2. Выберите вариант

| Ваш случай | Вариант |
| --- | --- |
| Сервер дома, пользоваться будете только из домашней сети (Wi-Fi) | **А. Домашняя сеть** — проще, домен не нужен |
| Сервер в интернете, хотите заходить откуда угодно, есть свой домен | **Б. С доменом и HTTPS** |

Не уверены — берите **А**. Перейти на **Б** можно позже.

## Шаг 3А. Установка для домашней сети

Скопируйте и вставьте одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/g99see/pulse-selfhosted/master/scripts/install.sh | sudo bash -s -- --http
```

Установщик сам найдёт IP сервера. Если хотите указать его явно, добавьте в конец `--host 192.168.1.50`.

Что будет происходить (ничего нажимать не нужно):

1. `Проверяю систему`: память, место на диске, порты.
2. `Устанавливаю Docker`: 1–3 минуты.
3. `Получаю код в /opt/puls` и `Генерирую .env`: создаются пароли и ключи шифрования.
4. `Собираю и запускаю стек (первая сборка — 10–20 минут)`: самое долгое, идут строчки `[120 c] ...`.
5. `Создаю первого администратора`.
6. `Готово`.

✅ В конце вы увидите примерно такое:

```text
==> Готово
    Сайт:           http://192.168.1.50
    Администратор:  admin@puls.local, пароль — в /root/puls-credentials.txt (chmod 600)
```

Переходите к [шагу 4](#шаг-4-первыи-вход).

## Шаг 3Б. Установка с доменом и HTTPS

**Сначала** настройте домен. У регистратора домена (где вы его купили) добавьте запись типа **A**,
она указывает на IP вашего сервера:

| Имя | Тип | Значение |
| --- | --- | --- |
| `puls` (получится `puls.example.com`) | A | IP сервера |

Подождите 5–30 минут, пока записи разойдутся. Проверить можно командой `ping puls.example.com`:
должен отвечать IP вашего сервера.

Порты **80 и 443** на сервере должны быть открыты из интернета (у VPS обычно открыты сразу,
для домашнего сервера нужен проброс портов на роутере).

Затем запустите (подставьте свой домен и почту):

```bash
curl -fsSL https://raw.githubusercontent.com/g99see/pulse-selfhosted/master/scripts/install.sh | sudo bash -s -- \
  --domain puls.example.com --email you@example.com
```

Почта нужна только для уведомлений о сертификате от Let's Encrypt. Сертификат HTTPS выпустится
сам при первом открытии сайта, это до минуты.

✅ В конце: `Сайт: https://puls.example.com`.

## Шаг 4. Первый вход

1. Посмотрите пароль администратора. На сервере выполните:

   ```bash
   sudo cat /root/puls-credentials.txt
   ```

   Там будут `Email`, `Никнейм` и `Пароль`. Сохраните пароль в менеджер паролей.

2. На телефоне или компьютере откройте адрес из строки `Сайт:` (например `http://192.168.1.50`).
3. Нажмите **«Войти»**, введите email и пароль из файла.
4. Пройдите короткую настройку: язык, **основная валюта**, часовой пояс, первый счёт.

::: warning Валюту выберите сразу
Основная валюта задаётся на этом шаге, и в настройках её потом не поменять. У каждого счёта
может быть своя валюта, курсы задаются в «Финансы → Курсы валют».
:::

✅ Вы видите экран «Сегодня». Сервис работает.

## Шаг 5. Создайте профили для близких

Без настроенной почты (SMTP) люди **не смогут зарегистрироваться сами**: им не придёт письмо
с подтверждением. Поэтому установщик включает режим «только по приглашению», и профили
создаёт администратор, то есть вы. Это делается одной командой на сервере.

**Создать профиль:**

```bash
sudo /opt/puls/scripts/users.sh add mama@example.com mama
```

Здесь `mama@example.com` — почта человека (она будет логином, проверять её никто не будет,
но лучше настоящую), `mama` — ник: латиница, цифры, `-` и `_`, от 3 до 32 символов.

✅ Ответ:

```text
Готово: mama@example.com (@mama).
При первом входе человек пройдёт короткую настройку: валюта, часовой пояс, первый счёт.

  Пароль: hT7kPq2mWx9dRf4a
  Покажу только сейчас: перепишите или передайте человеку.
```

Передайте человеку адрес сайта, почту и пароль. Пароль показывается **один раз**. Если потеряли,
сделайте новый (см. ниже).

**Ещё варианты:**

```bash
# английский интерфейс для этого человека
sudo /opt/puls/scripts/users.sh add john@example.com john --locale en

# сразу сделать администратором
sudo /opt/puls/scripts/users.sh add partner@example.com partner --admin

# свой пароль вместо придуманного (минимум 8 символов)
sudo /opt/puls/scripts/users.sh add kid@example.com kid --password "СвойПароль123"
```

::: tip Данные разделены
Каждый профиль отдельный: свои счета, траты и дневник, другие пользователи их не видят.
:::

## Шаг 6. Управление профилями

Все команды выполняются на сервере, полный список: `sudo /opt/puls/scripts/users.sh help`.

| Что нужно | Команда |
| --- | --- |
| Посмотреть всех | `sudo /opt/puls/scripts/users.sh list` |
| **Забыли пароль**: выдать новый | `sudo /opt/puls/scripts/users.sh password mama@example.com` |
| Сделать администратором | `sudo /opt/puls/scripts/users.sh role mama@example.com admin` |
| Снять права администратора | `sudo /opt/puls/scripts/users.sh role mama@example.com user` |
| Человек зарегистрировался сам, но письмо не пришло | `sudo /opt/puls/scripts/users.sh verify mama@example.com` |
| Узнать режим регистрации | `sudo /opt/puls/scripts/users.sh registration` |
| Разрешить всем регистрироваться самим | `sudo /opt/puls/scripts/users.sh registration open` |
| Запретить регистрацию совсем | `sudo /opt/puls/scripts/users.sh registration closed` |

После смены пароля человек выходит со всех устройств и входит заново с новым паролем.

::: warning Открытая регистрация
`registration open` включайте, только если настроили почту (раздел ниже). Иначе люди
зарегистрируются, но войти не смогут, пока вы не выполните для них `verify`. А если сервер
смотрит в интернет, зарегистрироваться сможет кто угодно.
:::

**Удалить профиль** может сам человек: «Настройки → Данные и приватность → Удалить аккаунт».
Все его данные удалятся безвозвратно. Перед этим там же можно скачать экспорт (JSON или CSV).

## Почта (по желанию)

Почта нужна, чтобы люди регистрировались сами и получали уведомления на email. Подойдёт
любой SMTP: почтовый ящик Gmail/Яндекс с паролем приложения или сервис рассылок.

1. Откройте файл настроек:

   ```bash
   sudo nano /opt/puls/.env
   ```

2. Найдите строку `SMTP_URL=` и впишите свои данные, например:

   ```text
   SMTP_URL=smtp://you%40gmail.com:пароль-приложения@smtp.gmail.com:587
   MAIL_FROM=Пульс <you@gmail.com>
   ```

   Символ `@` внутри логина пишется как `%40`.
   Сохранить: `Ctrl + O`, Enter, выйти: `Ctrl + X`.

3. Примените:

   ```bash
   cd /opt/puls && sudo docker compose up -d api
   ```

## HTTPS через Tailscale (по желанию)

Для уведомлений HTTPS **не нужен**: они приходят в Telegram и Discord, а не в браузер, и
работают даже по адресу вида `http://192.168.1.50`. HTTPS пригодится, если вы хотите открывать
Пульс с телефона вне дома по защищённому адресу. Самый простой способ получить HTTPS дома, без домена и открытых портов, — Tailscale.
Обычный адрес по домашней сети при этом продолжает работать: сайт будет открываться сразу двумя
способами.

1. Поставьте Tailscale на сервер и войдите в аккаунт:

   ```bash
   curl -fsSL https://tailscale.com/install.sh | sh
   sudo tailscale up
   ```

   Команда напечатает ссылку. Откройте её в браузере и подтвердите вход.

2. В админке Tailscale (login.tailscale.com → страница **DNS**) включите **MagicDNS** и
   **HTTPS Certificates**. Там же видно имя вашей сети, вида `tailXXXX.ts.net`.

3. Дайте серверу имя `puls` (или любое другое) и включите проксирование на Пульс:

   ```bash
   sudo tailscale set --hostname=puls
   sudo tailscale serve --bg --https=443 http://127.0.0.1:8081
   ```

4. Откройте файл настроек `sudo nano /opt/puls/.env` и впишите (подставьте своё имя вместо
   `puls.tailXXXX.ts.net`):

   ```text
   PUBLIC_API_URL=/
   COOKIE_SECURE=auto
   EXTRA_ORIGINS=https://puls.tailXXXX.ts.net
   ```

   Сохранить: `Ctrl + O`, Enter, выйти: `Ctrl + X`.

5. Примените (сервис пересоберётся):

   ```bash
   sudo /opt/puls/scripts/upgrade.sh
   ```

6. На телефоне поставьте приложение **Tailscale**, войдите в тот же аккаунт и включите его.
   Откройте `https://puls.tailXXXX.ts.net`.

Дома по-прежнему можно открывать `http://192.168.1.50` — вход работает и там, и там.

::: tip Сервер в контейнере Proxmox (LXC)
Tailscale нужно устройство `/dev/net/tun`. На хосте Proxmox добавьте в файл
`/etc/pve/lxc/<id>.conf` две строки и перезапустите контейнер:

```text
lxc.cgroup2.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
```

:::

## Уведомления в Telegram

Бот пишет вам напоминания, а в чате можно записать чек-ин или трату. Ему не нужен ни домен,
ни HTTPS: по умолчанию сервер сам спрашивает у Telegram, есть ли новые сообщения.

1. В Telegram найдите **@BotFather** и отправьте ему `/newbot`.
2. Придумайте имя бота, затем логин — он обязательно заканчивается на `bot`, например
   `my_puls_bot`.
3. BotFather пришлёт **токен** — длинную строку. Скопируйте её.
4. Откройте `sudo nano /opt/puls/.env` и впишите (имя бота — без `@`):

   ```text
   TELEGRAM_BOT_TOKEN=123456:ABC-токен-от-BotFather
   TELEGRAM_BOT_USERNAME=my_puls_bot
   ```

5. Перезапустите API:

   ```bash
   cd /opt/puls && sudo docker compose up -d api
   ```

6. На сайте откройте **Настройки → Уведомления**, найдите карточку Telegram и нажмите **«Подключить Telegram»**.
   Откроется чат с вашим ботом — нажмите **Start**. Экран в Pulse сам переключится на
   «Привязан» (никуда вводить код вручную не нужно). Отвязать можно кнопкой **«Отвязать»**.

Если на сайте написано «Бот не настроен на сервере» — проверьте токен в `.env` и
повторите шаг 5.

## Уведомления в Discord

Discord-бот присылает те же уведомления личными сообщениями. Ему тоже не нужен ни домен, ни
HTTPS: бот сам подключается к Discord.

1. Откройте [discord.com/developers/applications](https://discord.com/developers/applications)
   и войдите в свой аккаунт Discord. Нажмите **New Application**, придумайте имя (например,
   «Пульс») и подтвердите.
2. На странице приложения, в самом верху (раздел **General Information**), скопируйте
   **Application ID** — это длинное число.
3. Слева откройте раздел **Bot**. Нажмите **Reset Token** и подтвердите — Discord покажет
   **токен**. Скопируйте его сразу: потом он не показывается, только пересоздаётся.
   Никому не показывайте токен — с ним можно управлять ботом.
4. Откройте `sudo nano /opt/puls/.env` и впишите:

   ```text
   DISCORD_BOT_TOKEN=токен-из-шага-3
   DISCORD_APPLICATION_ID=число-из-шага-2
   DISCORD_CLIENT_SECRET=секрет-из-раздела-OAuth2
   DISCORD_OAUTH_REDIRECT_URI=https://ваш-домен/api/discord/callback
   ```

   `DISCORD_CLIENT_SECRET` — в разделе **OAuth2 → General**; добавьте
   `https://ваш-домен/api/discord/callback` в **OAuth2 → Redirects**.

   Сохранить: `Ctrl + O`, Enter, выйти: `Ctrl + X`.

5. Перезапустите API:

   ```bash
   cd /opt/puls && sudo docker compose up -d api
   ```

6. На сайте откройте **Настройки → Уведомления**, в карточке Discord нажмите
   **«Подключить Discord»** и подтвердите доступ в открывшемся окне Discord. Экран в Pulse
   сам переключится на «Привязан» — вводить код не нужно. Поведение бота (личные сообщения)
   остаётся прежним.

Если бот перестал писать, на сайте появится пометка «Бот заблокирован или личные сообщения
закрыты». Напишите боту любое сообщение — доставка возобновится.

## Обновление

Когда выходит новая версия:

```bash
sudo /opt/puls/scripts/upgrade.sh
```

Скрипт сам сделает резервную копию, скачает новый код, пересоберёт и перезапустит сервис.
Ваши данные и настройки сохраняются.

## Резервные копии

Копия базы делается **автоматически раз в сутки** в папку `/opt/puls/backups`, хранятся
последние 7. Сделать копию прямо сейчас:

```bash
cd /opt/puls && sudo bash scripts/backup.sh
```

Скопируйте папку `backups` куда-нибудь ещё (на другой диск или в облако): если сломается сам
сервер, копии на нём не помогут.

Восстановление из копии (имя файла возьмите из `ls /opt/puls/backups`):

```bash
cd /opt/puls && sudo sh scripts/restore.sh backups/backup-20261001T224516Z.tar.gz
```

## Что-то пошло не так

**Первым делом** посмотрите, все ли части работают:

```bash
cd /opt/puls && sudo docker compose ps
```

Все строки должны быть `Up ... (healthy)`. Если какая-то `unhealthy` или `Exited`, посмотрите её журнал:

```bash
sudo docker compose logs --tail 50 api
```

(вместо `api` может быть `web`, `caddy`, `postgres`.)

| Симптом | Что делать |
| --- | --- |
| Установщик пишет `Порт 80 занят` | На сервере уже работает другой сайт (nginx, apache). Остановите его или ставьте Пульс на отдельную машину/контейнер |
| Мало памяти, сборка падает с `Killed` | Нужно минимум 2 ГБ. Добавьте swap или памяти виртуальной машине и запустите установщик ещё раз |
| Сайт не открывается с телефона | Телефон должен быть в той же Wi-Fi сети. Проверьте адрес: `http://`, а не `https://` в домашнем варианте |
| Пароль не подходит | `sudo /opt/puls/scripts/users.sh password <email>` выдаст новый |
| «Регистрация только по приглашению» | Так и задумано без почты. Создайте профиль командой из шага 5 |
| Docker внутри Proxmox LXC не запускается | В настройках контейнера включите **nesting** и **keyctl**, перезапустите контейнер |
| HTTPS-сертификат не выпускается | Проверьте, что обе DNS-записи указывают на сервер и порты 80/443 открыты из интернета |

Установщик можно **запускать повторно сколько угодно**: он ничего не сломает, пароли и данные
сохранятся. Подробный журнал установки: `/var/log/puls-install.log`.

Не помогло — создайте issue на [GitHub](https://github.com/g99see/pulse-selfhosted/issues) и
приложите вывод `docker compose ps` и `docker compose logs --tail 80 api web caddy`
(**удалите из него пароли и почты**, если они там есть).
