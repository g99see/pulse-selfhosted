# Безопасность и 2FA

На этой странице — всё, что касается **настройки входа на стороне
пользователя**: двухфакторная аутентификация (TOTP), резервные коды, пароли и
вход через Google/Telegram. Переменные окружения, которые задаёт владелец
инстанса (в том числе для OAuth), описаны в разделе
[Настройка (.env)](/guide/configuration).

## Пароли

Пароли хранятся хешированными алгоритмом **Argon2**. Сессии — серверные, cookie
`httpOnly`. Все изменяющие запросы защищены CSRF-токеном, на вход действует
ограничение частоты. Ничего из этого настраивать вручную не нужно.

## Двухфакторная аутентификация (TOTP)

2FA реализована по RFC 6238: HMAC-SHA1, шаг 30 секунд, 6 цифр, окно ±1.
Секрет хранится зашифрованным (**AES-256-GCM**), резервные коды — только
хешами, а шаг между вводом пароля и вводом кода защищён одноразовым пропуском.

### Включение

Секция «Двухфакторная аутентификация» на странице `/settings`:

1. Нажмите **«Включить 2FA»** — сервис сгенерирует секрет и вернёт
   `secret`, `otpauthUri` и `qrDataUrl` (QR-код).
2. Отсканируйте QR-код приложением-аутентификатором (Google Authenticator,
   Aegis, 1Password и т. п.) либо введите секрет вручную.
   Если ссылка не помещается в QR, `qrDataUrl` будет `null` — секрет и URI
   всё равно показываются для ручного ввода.
3. Введите 6-значный код — 2FA включится, и вы получите **10 резервных кодов**.

Резервные коды показываются один раз — сохраните их в надёжном месте. Код, которым
вы подтверждали включение, повторно использован быть не может.

### Вход с 2FA

При включённой 2FA обычный вход по паролю не выдаёт сессию сразу: API отвечает
`200 { twoFactorRequired: true, challengeToken }` **без сессии**, а страница
входа показывает шаг ввода кода. Введите код TOTP **или** один из резервных
кодов — вход завершится.

Одноразовый пропуск `challengeToken` живёт 5 минут. Повтор кода TOTP в одном
окне и повтор резервного кода отклоняются. Лимит попыток второго фактора — 5 на
пропуск и 20 на IP за 15 минут (при превышении — `429`).

### Выключение

2FA отключается по **паролю и коду** в той же секции `/settings`.

::: warning Владельцу инстанса
Для работы 2FA в продакшене обязательна переменная `APP_ENCRYPTION_KEY` —
мастер-ключ AES-256-GCM ровно на 32 байта в base64. Без неё (`NODE_ENV=production`)
2FA **недоступна**: настройка отвечает `503 two_factor_unavailable`, а статус
возвращает `available: false`. Никакого «тихого» отката к небезопасному ключу не
происходит. В dev/test используется отдельный детерминированный тестовый ключ.
:::

## Резервные коды и завершение сессий

- Резервные коды одноразовые: при использовании отмечается `used_at`, повтор не
  проходит.
- Повторно принятый шаг TOTP (код из уже использованного окна) отклоняется —
  принимается только шаг строго больше.
- Если вы подозреваете компрометацию, смените пароль, отключите и заново включите
  2FA (это выдаст новый набор резервных кодов) и завершите активные сессии.

## Вход через Google и Telegram (OAuth)

Дополнительные способы входа включаются владельцем инстанса заданием ключей
провайдера (см. [Настройка (.env)](/guide/configuration)). Без ключей провайдер
выключен: кнопки в интерфейсе скрыты, а эндпоинты отвечают
`404 provider_disabled`.

- **Google** — OAuth2/OIDC, поток authorization code + PKCE. Перед редиректом
  создаётся `state`, который дублируется в httpOnly-cookie; повторный callback с
  тем же `state` отклоняется. `id_token` проверяется по JWKS Google (подпись
  RS256, сроки, issuer, audience).
- **Telegram** — Telegram Login Widget, данные которого проверяются подписью
  HMAC-SHA256 с секретом из токена бота; `auth_date` не старше 24 часов.
- Привязка аккаунта: если у Google-аккаунта подтверждённый email совпадает с
  существующим пользователем, вход привязывается к нему; иначе создаётся новый
  пользователь (без пароля). Для Telegram-аккаунтов без email показывается мягкая
  подсказка указать настоящий адрес.
- Отвязать способ входа можно в секции «Способы входа» на `/settings` — кроме
  случая, когда это единственный доступ (тогда `409 last_login_method`).
