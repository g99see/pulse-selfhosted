# Капсула времени

Письмо себе, которое открывается через месяц или год — вместе со статистикой
периода между созданием и открытием. Реализация — ТЗ §4 (P2). Экран живёт в
`apps/web/src/app/(app)/capsules/page.tsx` (адрес `/capsules`).

## Что это

Модель `TimeCapsule` (`apps/api/prisma/schema.prisma`) хранит `id`, `user_id`,
`title`, `body_encrypted`, `snapshot`, `open_at`, `opened_at`, `created_at`.
Тело письма шифруется AES-256-GCM (`crypto/secret-box.ts`), `snapshot` — JSON со
статистикой периода. Схема добавлена миграцией `20261001175000_time_capsules`
(идемпотентная, `IF NOT EXISTS`).

## Действия и ограничения

| Что | Как |
| --- | --- |
| Создание | Пресет даты («через месяц» / «через год», с зажимом дня) либо произвольный `openAt` |
| Границы срока | от **+1 суток** до **+10 лет** от создания |
| Список | Только метаданные капсул — тело не отдаётся |
| Чтение | До `open_at` — только метаданные; после — расшифрованное письмо и снимок статистики |
| Удаление | Только своей капсулы |

Пресеты дат, границы срока, проверка доступности и сборка снимка вынесены в
чистые функции `packages/shared/src/capsules.ts` (unit-тесты —
`test/capsules.test.ts`, 14 тестов).

## Снимок статистики периода

Снимок собирается в момент **открытия** за интервал `[created_at, open_at]`:

- траты и доходы по `daily`-границам в часовом поясе пользователя (только
  `expense` / `income`);
- среднее настроение и число чек-инов;
- состояние целей на момент открытия (`title`, `target`, `saved`, `percent`).

Снимок сохраняется в `snapshot` и переиспользуется при повторном чтении. У
накопительных целей периода нет, поэтому в снимке они — как состояние «на
сейчас».

## Планировщик

`CapsulesScheduler` (по образцу `notifications/scheduler.ts`) работает на
BullMQ/Valkey с таймерным фолбэком. Захват идёт через CAS по `opened_at`; в
момент `open_at` собирается снимок и уходит уведомление «капсула открылась»
через `NotificationDispatcher::notifyCapsuleOpened`. Автостарт выключен в
тестах (`NODE_ENV=test`); управляется переменными `CAPSULES_SCHEDULER` и
`CAPSULES_TICK_MS`.

## Приватность и выгрузка

- Тело письма (`body_encrypted`) **не отдаётся**, пока `now < open_at`. API
  возвращает только `title`, `open_at`, `opened_at`, `created_at`.
- В реестре выгрузки (`account/data-registry.ts`) `time_capsules` объявлена с
  `secretColumns: ['body_encrypted']`: колонка распознаётся как секрет
  (`isSecretColumn`, суффикс `_encrypted`) и в выгрузку тела **не попадает**.
  Это сознательное решение — выгрузка идёт по колонкам. Владелец читает письмо
  расшифрованным через `GET /api/capsules/:id` после открытия.
- Пока не задан `APP_ENCRYPTION_KEY` и окружение production, капсулы недоступны
  (`503 capsules_unavailable`) — как и 2FA.

## API

Все маршруты — под `SessionGuard` (`/api/capsules`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/` | Создать капсулу (тело шифруется; срок — пресет или `openAt`) |
| GET | `/` | Список капсул (только метаданные) |
| GET | `/:id` | До `open_at` — метаданные, после — письмо и снимок статистики |
| DELETE | `/:id` | Удалить свою капсулу |
| POST | `/:id/dev-open` | Dev/e2e-хук открытия (в production отдаёт `404`) |

Ошибки — в едином формате `{ code, message }`: `capsules_unavailable`
(503, нет ключа шифрования в production); dev/e2e-хук вне dev-окружения —
`404`.
