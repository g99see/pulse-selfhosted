# Уведомления

«Пульс» напоминает о чек-инах, платежах и бюджете по расписанию с учётом вашего
часового пояса и тихих часов. Каналы — **web push** (PWA) и **email**; третий
канал, Telegram, описан в разделе [Telegram-бот](./telegram).

Реализация соответствует ТЗ §3.6 и сценарию 1 из §5: push с чек-ином приходит по
расписанию, а ответ на него сохраняется прямо из уведомления.

## Типы и каналы

| Тип | Обозначение | О чём напоминает |
| --- | --- | --- |
| Чек-ины | `checkins` | «Как ты себя чувствуешь?» |
| Платежи | `payments` | О регулярном платеже |
| Бюджет | `budget` | Предупреждение бюджета |
| Недельный отчёт | `weekly_report` | Еженедельный разбор |
| Реакции | `reactions` | Реакция или комментарий к вашему посту |

Каждый тип включается и выключается отдельно. Каналы: `web_push` и `email`.

## Расписание и тихие часы

- Расписание по умолчанию — **3 раза в день**: `09:00`, `15:00`, `21:00`
  (утро / день / вечер). Настраивается от 1 до 6 слотов.
- Тихие часы по умолчанию — **22:00–08:00**, включая переход через полночь.
  Слот, попавший в тихие часы, переносится на их конец (утренний — на тот же
  день, поздний вечерний — на следующий).
- Всё считается в IANA-часовом поясе пользователя; переходы на летнее/зимнее
  время пересчитываются по смещению зоны в найденном моменте, а не по
  фиксированному сдвигу.
- **Умное время**: если вы обычно отвечаете, например, в 9:30, утренний вопрос
  сдвигается на это время (медиана привычного времени ответа).

Расписание хранится в JSONB-поле правила, например:

```json
{ "times": ["09:00", "15:00", "21:00"] }
```

## Правила уведомлений

Настройки находятся в карточке «Уведомления» на странице `/app/profile`:

- переключатели по каждому из пяти типов;
- тихие часы («с» и «до»);
- кнопка **«Включить push»** и **«Отключить push»**.

Правила хранятся лениво: `GET /api/notifications/rules` отдаёт сохранённые
значения поверх значений по умолчанию, а `PUT /api/notifications/rules` меняет
только присланные типы (upsert).

## Web push и ключи VAPID

Push работает через Web Push с ключами VAPID. Ключи задаются переменными
окружения (см. [Настройка (.env)](/guide/configuration)):

```
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:admin@example.com
NOTIFICATIONS_SCHEDULER=on        # off — выключить планировщик
NOTIFICATIONS_TICK_MS=60000       # период тика, мс
```

Сгенерировать пару ключей можно командой:

```bash
pnpm --filter @puls/api vapid:generate
```

Если ключи не заданы или некорректны, отправка push просто отключается — API
продолжает работать, а `GET /api/notifications/vapid-public-key` честно
возвращает `{ publicKey: null, enabled: false }` и пишет предупреждение в лог.
Просроченные подписки (ответы `404`/`410`) удаляются автоматически.

## Эндпоинты

Все эндпоинты — с префиксом `/api/notifications`.

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| GET | `/vapid-public-key` | публичный | `{ publicKey, enabled }` |
| GET | `/subscriptions` | сессия | Подписки текущего пользователя |
| POST | `/subscriptions` | сессия | Сохранить подписку (upsert по `endpoint`) |
| DELETE | `/subscriptions` | сессия | Удалить свою подписку по `endpoint` |
| GET | `/rules` | сессия | Эффективные правила по всем типам |
| PUT | `/rules` | сессия | Типы, расписание, тихие часы |

Данные строго изолированы по пользователю: чужая подписка недоступна.

## Планировщик

`NotificationsScheduler` раз в минуту выбирает пользователей с включёнными
уведомлениями, считает «созревшие» доставки в окне между прошлым и текущим
тиком и отправляет их через диспетчер.

- В продакшене тик идёт через **BullMQ** на Valkey — повторяемая задача
  `notifications-tick`.
- Если `REDIS_URL` не задан или Valkey недоступен, планировщик переходит на
  таймер в процессе и пишет предупреждение; API не падает.
- Отключить планировщик целиком можно через `NOTIFICATIONS_SCHEDULER=off`.

## Ответ на чек-ин прямо из push

Push-уведомление чек-ина несёт кнопки настроения `mood-1`…`mood-5` (эмодзи).
Нажатие кнопки в уведомлении отправляет ответ без открытия сайта: service worker
делает `POST /api/checkins` с телом `{ mood }`.

::: tip Форматы ответа
Помимо `/api/checkins`, для того же сценария есть быстрый путь
`POST /api/checkins/quick`, принимающий `{ mood }`.
:::

## Email-канал

Для правил с каналом `email` планировщик использует `MailService.sendNotification`:
письмо содержит тему, текст и ссылку. Тексты писем и push собираются из одних и
тех же чистых функций — формулировки каналов совпадают.

## PWA

Установка приложения и офлайн-страница работают через Serwist: service worker
кеширует статику и отдаёт офлайн-страницу для навигационных запросов, а
уведомления показываются из `push`-события. Кнопка «Установить» доступна в
`/app/profile` (на iOS Safari показывается подсказка). Подробнее об установке —
в разделе про PWA.

::: warning Честно о проверке
Чистая логика выбора доставок и разовый прогон планировщика покрыты
unit-тестами без Valkey. Реальная интеграция с Valkey/BullMQ (создание очереди и
воркера, повторяемая задача) автоматическими тестами **не проверялась** — для
неё нужен доступный Valkey и запущенный API.
:::
