# Уведомления

«Пульс» напоминает о чек-инах, подводит итог дня и предупреждает о бюджете по расписанию с учётом
вашего часового пояса и тихих часов. Уведомления приходят **только в мессенджеры — Telegram и
Discord**. Браузер ничего не запрашивает: разрешений на уведомления, push-подписок и ключей VAPID
больше нет.

## Каналы

| Канал | Что нужно | Как привязать |
| --- | --- | --- |
| Telegram | `TELEGRAM_BOT_TOKEN` | **Настройки → Уведомления → Telegram → «Привязать»**, код отправить боту: `/start КОД` |
| Discord | `DISCORD_BOT_TOKEN`, `DISCORD_APPLICATION_ID` | **Настройки → Уведомления → Discord → «Привязать»**, код отправить боту в личные сообщения: `/link КОД` (или команда `/link` с полем `code`) |

Каждый канал настраивается отдельно: включён ли он, расписание чек-инов, время итога дня, тихие
часы, часовой пояс (по умолчанию — из профиля) и переключатели по типам. Пошаговое создание ботов —
в [быстром старте](/guide/quick-start). Telegram-бот описан в разделе [Telegram-бот](./telegram).

## Типы уведомлений

| Тип | Обозначение | О чём |
| --- | --- | --- |
| Чек-ины | `checkins` | «Как ты себя чувствуешь?» (в Telegram — с кнопками 1–5) |
| Итог дня | `daily_summary` | Траты, доходы, настроение и число чек-инов за день |
| Платежи | `payments` | О регулярном платеже за день до списания |
| Бюджет | `budget` | Бюджет категории дошёл до 80% или превышен (один раз на порог) |
| Расхождение баланса | `reconciliation_mismatch` | Остаток счёта не сходится с операциями |
| Недельный отчёт | `weekly_report` | Еженедельный разбор |
| Реакции | `reactions` | Реакция или комментарий к вашему посту |

Тип `reconciliation_mismatch` — готовый хук для сверки счетов: любой код вызывает
`NotificationDispatcher.notifyReconciliationMismatch(userId, { accountName, difference })`, и
уведомление уходит в каналы, где тип включён.

## Расписание и тихие часы

- Чек-ины — **3 раза в день** по умолчанию: `09:00`, `15:00`, `21:00`; настраивается от 1 до 6.
- Итог дня — в `21:30` по умолчанию.
- Тихие часы по умолчанию — **22:00–08:00**, включая переход через полночь. Плановый слот,
  попавший в тихие часы, переносится на их конец; событийные уведомления (бюджет, платёж) ждут
  окончания тихих часов в очереди.
- Всё считается в часовом поясе канала (если не задан — в поясе профиля); переходы на летнее и
  зимнее время учитываются.

## Надёжная доставка (outbox)

Каждое сообщение сначала записывается в таблицу `notification_deliveries` со статусом `queued`.
Воркер планировщика раз в 15 секунд отправляет созревшие записи:

- успех → `sent`;
- временная ошибка → запись остаётся `queued`, повтор по экспоненте: 30 с, 1, 2, 4 мин… (максимум
  час); уважается `Retry-After` от Telegram и Discord;
- после **5 неудачных попыток** → `failed`;
- Telegram ответил `403` («бот заблокирован») или Discord — код `50007` (личные сообщения
  закрыты) → привязка помечается заблокированной, оставшиеся записи получают статус `blocked`,
  новые не ставятся. Как только пользователь снова напишет боту, блокировка снимается.

В настройках видны **последние 20 отправок** со статусом, числом попыток и временем.
Администратор получает счётчики по статусам: `GET /api/admin/notifications/metrics`.

## Бюджет и сверка в мессенджер

Предупреждения бюджета (80% и превышение) ставятся в очередь при любом новом
расходе: через API и веб, быстрый ввод, `/spent` в боте и импорт выписки (после
импорта проверяется каждая затронутая категория и месяц). Если после импорта
выписки сверка находит ненулевую необъяснённую разницу, приходит уведомление
«Баланс не сходится» — **один раз на выписку** (повторная загрузка того же файла
молчит).

## Итог дня по ссылке

В настройках можно создать секретную ссылку `/d/<токен>`: без входа она показывает
итоги сегодняшнего дня — траты, доходы, среднее настроение и число чек-инов, без
операций и заметок. Токен показывается один раз (в БД — только хеш), ссылку можно
перевыпустить (старая перестаёт работать) или отозвать.

## Миграция с web push

При обновлении таблица `push_subscriptions` удаляется, а правила уведомлений с каналом `web_push`
(и `email`) переводятся на `telegram`. Расписание и тихие часы переезжают в настройки канала.
Чтобы получать уведомления, привяжите Telegram или Discord.

## Эндпоинты

Все — под сессией, данные строго изолированы по пользователю.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/notifications/channels` | Состояние и настройки обоих каналов |
| PUT | `/api/notifications/channels/:channel` | Частичное обновление (`telegram` или `discord`) |
| GET | `/api/notifications/deliveries` | Последние 20 доставок |
| GET | `/api/admin/notifications/metrics` | Счётчики outbox по статусам (только admin) |
| GET / POST / DELETE | `/api/discord/status`, `/link-code`, `/link` | Привязка Discord |
| GET / POST / DELETE | `/api/telegram/status`, `/link-code`, `/link` | Привязка Telegram |

## Планировщик

`NotificationsScheduler` раз в минуту выбирает пользователей с включёнными уведомлениями и
ставит «созревшие» плановые уведомления в outbox; отдельный воркер отправляет очередь.

- В продакшене тик идёт через **BullMQ** на Valkey; если `REDIS_URL` не задан или Valkey
  недоступен — таймер в процессе (API не падает).
- `NOTIFICATIONS_SCHEDULER=off` выключает планировщик и воркер.

## PWA

Установка приложения и офлайн-страница работают через Serwist: service worker кеширует статику и
отдаёт офлайн-страницу. Push-обработчиков в нём нет, а разрешение на уведомления браузер не
запрашивает.
