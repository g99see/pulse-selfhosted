# Статистика и рекомендации

Раздел собирает данные финансов и чек-инов в статистику, а на её основе даёт
рекомендации. Статистика — ТЗ §3.4, рекомендации — ТЗ §3.5. Экраны живут в
`app/(app)/stats` и `app/(app)/insights`.

## Экраны

| Экран | Маршрут | Что делает |
| --- | --- | --- |
| Статистика | `/stats` | Переключатель периода (день / неделя / месяц / год), итоги, сравнение периодов, график трат, траты по категориям, тепловая карта настроения |
| Рекомендации | `/insights` | Лента инсайтов, оценка «Полезно / Не полезно», кнопка «Применить», блок служб поддержки |
| Главная | `/app` | Блок дашборда дня и блок «Последнее наблюдение» |

## Дашборд дня

Блок на `/app` (`components/today-stats.tsx`) показывает траты, доходы, остаток
бюджета, среднее настроение и число чек-инов. Он слушает событие
`puls:finance-changed` и обновляется сразу после быстрого ввода траты.

## Отчёты за период

Отчёт отдаёт траты по категориям, доходы против расходов, ряд по дням для
графика и сравнение с предыдущим таким же периодом (процентная разница).

- Периоды: `day`, `week`, `month`, `year`; по умолчанию — `month`.
- Без параметра `date` берётся текущий день в часовом поясе пользователя.
- Неделя считается с понедельника по воскресенье, месяц и год — календарные.

### Границы дней по часовому поясу

Границы считаются в часовом поясе пользователя (`users.timezone`):

| Функция | Смысл |
| --- | --- |
| `dayKeyInTimezone(instant, tz)` | К какому дню относится момент (чек-ин в 22:30 UTC — уже следующий день в Москве и ещё текущий в UTC) |
| `zonedDayBounds(dayKey, tz)` | UTC-интервал `[начало, конец)` дня с учётом перехода на летнее/зимнее время (день длиной 25 и 23 часа) |
| `periodRangeFromDay(period, dayKey)` | Диапазон периода |

Транзакции хранят дату как `@db.Date` (календарный день операции), поэтому их
день не сдвигается часовым поясом; пояс влияет на чек-ины (у них timestamp) и на
определение «сегодня».

## Дневные агрегаты и кеш

- `DailyStat` — `user_id`, `date`, `spent`, `earned` (`Decimal(14,2)`),
  `avg_mood` (`Float?`), `checkins_count`, уникальность `(user_id, date)`.
- `StatsService.recomputeRange` пересчитывает агрегаты **лениво** — при чтении
  статистики, а не при записи транзакции (`GET /stats/day` пересчитывает день
  перед ответом). Модуль финансов о статистике не знает.
- В `DailyStat` попадают только дни с данными плюс сегодняшний день, поэтому
  дашборд готов к пустому дню.
- Запись — `upsert` по `(user_id, date)` в одной транзакции БД, поэтому кеш не
  расходится с данными. Источник истины — таблицы `transactions` и `check_ins`,
  `DailyStat` — только кеш.

Математика — чистые функции `packages/shared/src/stats.ts`: `sumSpent` /
`sumEarned` (переводы между счетами не расход), `groupSpentByCategory`,
`budgetRemaining`, `buildMoodCalendar`, `comparePeriods`, `moodAverage`,
`roundMoney`.

## Графики и тепловая карта

- Графики — простые SVG без тяжёлых библиотек (`lib/charts.ts`: раскладка
  столбцов, уровень тепловой карты, сводка ряда).
- **Тепловая карта настроения** — календарь за месяц: каждый день окрашен по
  среднему настроению (`buildMoodCalendar`).
- Доступность (WCAG 2.1 AA): у каждого SVG есть `role="img"`, `<title>` и
  `<desc>` с текстовым описанием; у тепловой карты — скрытый список дней со
  значениями настроения; переключатель периода — `role="group"` с `aria-pressed`.

## Самочувствие и траты

Карточка «Самочувствие и траты» на экране «Рекомендации» сравнивает средние траты
за день в «плохие» и обычные дни по трём метрикам: сон меньше 6 часов, энергия
ниже 3, настроение ниже 3 (окно — 60 дней, данные — `DailyStat`: `avgSleep`,
`avgEnergy`, `avgMood`, `spent`). Вывод появляется, только если в каждой группе
не меньше 4 дней; в ленту инсайтов попадает, если траты в плохие дни выше на
15% и больше («в дни с недосыпом вы тратите на 40% больше»). Это наблюдение о
привычках, а не причинная связь. Данные: `GET /api/insights/correlations`.

::: info Не сделано
Графики корреляций «настроение против тегов и дня недели» (ТЗ §3.4) пока не
реализованы; трекер привычек есть отдельно ([Привычки](/guide/usage/habits)), в
дашборде вместо «выполненных привычек» показывается число чек-инов.
:::

## Рекомендации на правилах

Движок читает траты, чек-ины и бюджеты из уже готовых сервисов и формирует
текстовые наблюдения. Без медицинских диагнозов. AI-разбор по запросу
(ТЗ §3.9, Фаза 4) здесь намеренно не реализован.

### Правила

Правила — чистые функции `packages/shared/src/insights.ts`:

| Правило | Текст (ключ i18n) |
| --- | --- |
| Траты на категорию выросли на N% за неделю | `insights.text.categorySpendUp` |
| Три дня подряд энергия ниже 2 | `insights.text.lowEnergyStreak` |
| Настроение выше в дни со спортом (по тегу) | `insights.text.moodWithSport` |
| Превышение бюджета | `insights.text.budgetExceeded` |
| Предложение недели: бюджет на категорию | `insights.text.budgetSuggestion` |
| Защитное правило: настроение 1 дольше 5 дней | `insights.text.wellbeingConcern` |

Пороговые значения: рост категории ≥ 20% при сумме ≥ 300; серия низкой энергии
≥ 3 дней; разница настроения со спортом ≥ 0.5 при ≥ 3 днях с тегом; тревожный
сигнал — **6 и более** дней подряд (буквально «более 5 дней» из ТЗ §3.5).

### Еженедельный разбор

- Собирается в **воскресенье в 19:00** по часовому поясу пользователя
  (`weeklyReportSlot` / `isWeeklyReportDue`), идемпотентно по ISO-неделе.
- Состав — `selectWeeklyInsights`: **3 самых весомых инсайта и 1 предложение**.
- Уведомление отправляется типом `weekly_report` (канал — правило пользователя,
  по умолчанию email).

### Оценка «полезно / нет»

Каждая рекомендация оценивается. Оценки влияют на показ: тип прячется при ≥ 2
оценках «не полезно» без одобрений (`hiddenInsightTypes`). Функции
`insightTypePenalty`, `rankInsights`, `feedbackStatsFromRows` учитывают оценки.

### Применение предложения

`POST /api/insights/:id/apply` применяет предложение и создаёт бюджет через
`BudgetsService`: месячный лимит = недельный × 30 / 7.

## Службы поддержки

При тревожном инсайте (`wellbeingConcern`) сервис мягко предлагает обратиться к
специалисту и показывает контакты служб страны пользователя. Страна
определяется по часовому поясу (`countryFromTimezone`), к контактам страны
добавляется международный. Формулировки без диагнозов и обещаний лечения.

## Достижения и стрики

- **Стрики чек-инов** — серия дней подряд по календарным дням в часовом поясе
  пользователя. Пропуск дня сбрасывает серию; если сегодня чек-ина ещё нет, серия
  не обнуляется. Переходы на летнее время учитываются.
- **Достижения (бейджи)**: первый чек-ин; серии 7/30/100 дней; первая транзакция;
  первый закрытый бюджет (прошедший месяц без превышения лимита); цели — первая
  цель, половина (50%) и завершение (100%).
- Экран `/achievements` — сетка бейджей по группам (чек-ины, финансы, цели):
  полученные и нет, дата получения, прогресс до порога; карточка серии с
  прогресс-баром до следующей награды.
- Карточка чек-ина на `/app` показывает текущую серию и запускает конфетти при
  получении нового бейджа (уважает `prefers-reduced-motion`).

## API

### Статистика (`/api/stats`, под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/day?date=YYYY-MM-DD` | Дашборд дня: траты, доходы, остаток бюджета, среднее настроение, чек-ины |
| GET | `/report?period=day\|week\|month\|year&date=YYYY-MM-DD` | Отчёт: траты по категориям, доходы против расходов, ряд по дням, сравнение с прошлым периодом |
| GET | `/mood-calendar?month=YYYY-MM` | Календарь-тепловая карта: среднее настроение по каждому дню месяца |

### Рекомендации (`/api/insights`, под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Лента (генерирует свежие за сегодня); при тревожном инсайте добавляет `support` и `country` |
| GET | `/latest` | Последний инсайт для блока на главной |
| GET | `/weekly` | Последний недельный разбор |
| POST | `/:id/feedback` `{ feedback }` | Оценка «полезно / нет» |
| POST | `/:id/apply` | Применяет предложение (создаёт бюджет) |
| POST | `/generate` | Ручная генерация (идемпотентно) |

### Достижения (`/api/achievements`, под `SessionGuard`)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Ленивая проверка условий, список бейджей с прогрессом и текущая серия |
| GET | `/streak` | Только серия (для карточки чек-ина на `/app`) |

## Изоляция данных

Каждый запрос фильтруется по `user_id` текущей сессии: чужой пользователь не
видит ни трат, ни настроения, ни инсайтов (чужой инсайт — `404`, анонимный —
`401`). Закреплено тестом «Изоляция данных».
