# Чек-ины самочувствия

Чек-ин — ответ на вопрос «Как ты себя чувствуешь?» за несколько секунд. Реализация —
ТЗ §3.3. Заполнять можно настроение, энергию, стресс, сон, воду, шаги, теги и
заметку-дневник. Экран живёт в `app/(app)/checkin`.

## Экраны и карточка на главной

| Место | Что делает |
| --- | --- |
| `/app` | Карточка чек-ина: вопрос «Как ты себя чувствуешь?», шкала 1–5 эмодзи-кнопками и ссылка на страницу — ответ в одно нажатие |
| `/checkin` | Шкала настроения, расширенный чек-ин, поле «Что сегодня получилось?», история и расписание |

## Ответ за 5 секунд из уведомления

Push-уведомление чек-ина несёт кнопки настроения `mood-1`…`mood-5` (эмодзи) и
`checkinUrl` (по умолчанию `/api/checkins`). Service worker показывает
уведомление из `push`-события и по нажатию кнопки делает
`POST /api/checkins` с телом `{ mood }` — отвечать можно прямо из уведомления,
не открывая приложение. Для того же сценария есть отдельный быстрый путь
`POST /api/checkins/quick`, который принимает `{ mood }` и может быть передан в
`checkinUrl`.

Подробнее о каналах и расписании — [Уведомления](/guide/usage/notifications).

## Шкала настроения

Настроение — целое от 1 до 5. Цвета и эмодзи живут в `@puls/shared`
(`MOOD_COLORS`, `MOOD_EMOJI`). Палитра из ТЗ §8: `#7C8DB5` → `#D8D3CB` →
`#F5C542`; красный цвет не используется.

## Расширенный чек-ин

По желанию к настроению добавляются:

| Поле | Допустимый диапазон |
| --- | --- |
| Энергия | целое 1–5 |
| Стресс | целое 1–5 |
| Сон | часы, 0–24 |
| Вода | стаканы, 0–50 |
| Шаги | 0–200 000 |
| Теги | до 20 штук |
| Заметка | до 2000 символов |
| Вечерний итог дня (`daySummary`) | до 280 символов, одна строка |

**Вечерний итог** — поле «Что сегодня получилось?»: одна строка для дневника,
добавляется в чек-ин при создании или через правку (`PUT /api/checkins/:id`).
Заметка-дневник — свободный текст, который хранится в записи чек-ина.

## Провалы дня

У чек-ина есть слот `slot` — `morning`, `day` или `evening`. Это позволяет
вести отдельные отметки для утра, дня и вечера.

## Заполнение задним числом

Пропущенный чек-ин можно заполнить в течение **24 часов** от фактического
момента `occurredAt`. Старше окна — `400 checkin_window_expired`; время в
будущем — `400 validation_error`. «Сегодня» вычисляется по часовому поясу
пользователя (`dayBoundsInTimeZone`).

## Расписание напоминаний

Расписание хранится в `User` (`checkin_times_per_day`, по умолчанию 3, и
`checkin_times`, по умолчанию `['09:00','15:00','21:00']`) и настраивается от
**1 до 6** напоминаний в день.

- Времена — в формате `HH:MM` без повторов.
- Слот, попавший в тихие часы, переносится на их конец; переходы DST
  пересчитываются по смещению зоны, а не по фиксированному сдвигу.
- Умное время: если пользователь отвечает регулярно в 9:30, утренний слот
  сдвигается на 9:30.

Тихие часы и каналы (web push / email) настраиваются в разделе уведомлений —
см. [Уведомления](/guide/usage/notifications).

## Стрики

Серия дней подряд считается по календарным дням в часовом поясе пользователя:
пропуск дня сбрасывает серию, но если сегодня чек-ина ещё нет, серия не
обнуляется (день ещё не засчитан). Переходы на летнее время и границы суток
учитываются. Стрик показывается на карточке чек-ина на `/app`
(`checkin-streak`), а за серии 7/30/100 дней выдаются достижения — см.
[Статистика и рекомендации](./stats-insights).

## API

Все маршруты — под `SessionGuard`, данные только текущего пользователя
(`/api/checkins`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Список чек-инов за период (`?from&to&limit`) |
| GET | `/today` | Чек-ины текущего дня по часовому поясу пользователя |
| GET | `/schedule` | Расписание напоминаний (1–6 раз в день) |
| POST | `/` | Чек-ин: настроение + расширенные поля, `occurredAt` необязателен |
| POST | `/quick` | Ответ за 5 секунд: только настроение |
| GET | `/:id` | Один чек-ин (чужой → `404`) |
| PUT | `/schedule` | Сохранить расписание |
| PUT | `/:id` | Правка своего чек-ина (например, дописать итог дня) |
| DELETE | `/:id` | Удаление своего чек-ина |

Ошибки — в едином формате `{ code, message }`: `validation_error`,
`checkin_window_expired`, `checkin_not_found`, `unauthorized`.

## Изоляция данных

Каждый запрос фильтруется по `user_id` текущей сессии: чужой чек-ин не виден и
не редактируется (`404`). Закреплено интеграционным тестом «Изоляция данных».
