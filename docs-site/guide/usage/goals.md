# Цели накоплений

Цели накоплений — это сумма, срок и прогресс к ней. Реализация — ТЗ §3.2 и
сценарий 2 из ТЗ §5. Экран живёт в `app/(app)/goals`.

## Экран `/goals`

- **Кольцо прогресса** (SVG) для каждой цели.
- **Форма цели**: название, сумма (`target_amount`), срок (`deadline`),
  картинка (эмодзи-пресет или ссылка — загрузки файлов нет), приватность и
  необязательный счёт-сбережения.
- **Форма пополнения** с показом новой достигнутой вехи.

На главной `/app` карточка `GoalsCard` показывает кольца прогресса до двух целей
и ссылку на `/goals`; она обновляется по событию `puls:goals-changed`.

## Поля цели

Модель `Goal` (суммы — `Decimal(14,2)`):

| Поле | Смысл |
| --- | --- |
| `title` | Название цели |
| `target_amount` | Целевая сумма |
| `saved_amount` | Накоплено |
| `deadline` | Срок |
| `image` | Эмодзи-пресет или URL (без загрузки файлов) |
| `account_id` | Необязательный счёт-сбережения |
| `currency` | Валюта цели |

Цели личные: их видит только владелец.

История пополнений хранится в `GoalDeposit` (`goal_id`, `user_id`, `amount`,
`date`, необязательный `account_id`) и даёт фактический темп для прогноза даты
достижения. Пополнение со счёта списывает сумму со счёта в одной транзакции БД
вместе с записью пополнения и ростом `saved_amount`.

## Прогресс, взнос и прогноз

Расчёты вынесены в чистые функции `@puls/shared/src/goals.ts`:

| Функция | Что считает |
| --- | --- |
| `goalProgress(saved, target)` | Прогресс в %, 0..100 (не делит на ноль) |
| `requiredMonthlyContribution(target, saved, deadline, from)` | Нужный взнос в месяц: «120 000 ₽ к 1 марта → 24 000 ₽/мес» (`null`, если срок не задан; `0`, если цель достигнута) |
| `goalPacePerMonth(deposits, from)` | Фактический темп пополнений в месяц |
| `forecastGoalDate(saved, target, pace, from)` | Прогноз даты достижения по фактическому темпу |
| `reachedMilestones(percent)` / `crossedMilestones(previous, next)` | Вехи 25/50/75/100% |

Так работает сценарий 2 из ТЗ §5: цель «Ноутбук», 120 000 ₽ к 1 марта → сервис
считает взнос **24 000 ₽ в месяц**.

## Вехи и достижения

Вехи отмечаются на **25 / 50 / 75 / 100%**. Ответ на пополнение содержит событие
вехи — только те вехи, что пересечены **этим** пополнением:

```json
{
  "goal": { "savedAmount": 60000, "percent": 50, "milestones": [25, 50] },
  "deposit": { "amount": 60000, "date": "2026-10-01T00:00:00.000Z" },
  "milestone": { "percent": 50, "reached": [25, 50] }
}
```

По целям выдаются достижения: `first_goal` (первая цель), `goal_half` (50%) и
`goal_complete` (100%). Модуль целей вызывает публичный
`AchievementsService.award(userId, code)` — он идемпотентен, повторная выдача и
гонка двух вызовов дают ровно одну запись.

## Напоминания

Сервис рассчитывает **нужный взнос в месяц** и показывает прогноз даты
достижения. Предложение регулярного напоминания о взносе описано в ТЗ §3.2
(сценарий 2); фоновые напоминания о платежах и чек-инах рассмотрены в
[Уведомлениях](/guide/usage/notifications).

## API

Все маршруты — под `SessionGuard`, данные только текущего пользователя
(`/api/goals`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Список целей с прогрессом |
| GET | `/:id` | Одна цель |
| POST | `/` | Создание цели (сумма, срок, картинка, счёт) |
| PUT | `/:id` | Правка цели |
| DELETE | `/:id` | Удаление цели |
| POST | `/:id/deposit` | Пополнение цели |

Ошибки — в едином формате `{ code, message }`: `validation_error`,
`goal_not_found`, `account_not_found`, `unauthorized`.

## Изоляция данных

Каждый запрос фильтруется по `user_id` сессии: чужая цель не видна и не
меняется (`404`), пополнение с чужого счёта отклоняется (`404`). Закреплено
интеграционным тестом «Изоляция данных между пользователями».
