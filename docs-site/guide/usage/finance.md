# Финансы

Раздел финансов ведёт счета, доходы и расходы, бюджеты, регулярные платежи и
курсы валют. Реализация — ТЗ §3.2. Экраны живут в `app/(app)/finance` внутри
защищённого кабинета (общий `layout.tsx` проверяет сессию и онбординг).

## Экраны

| Экран | Маршрут | Что делает |
| --- | --- | --- |
| Финансы | `/finance` | Счета, список транзакций с фильтрами, бюджеты с прогресс-барами, секция регулярных платежей |
| Импорт выписки | `/finance/import` | Загрузка CSV-выписки банка, сопоставление колонок, предпросмотр и подтверждение |
| Курсы валют | `/finance/rates` | Ручное создание и правка курсов |

Кнопка «+» в каркасе приложения открывает **шторку быстрого добавления**: строка
ввода, выбор категории и необязательный комментарий. Сохранение — за три нажатия.

## Счета

У счёта есть название, тип и баланс. Типы счетов: `card` (карта), `cash`
(наличные), `savings` (сбережения). Баланс хранится как `Decimal(14,2)`, в API
отдаётся числом. Общий баланс — сумма по всем счетам.

## Транзакции

- Типы: **доход** и **расход**. Дата по умолчанию — сегодня, её можно изменить.
- У транзакции есть сумма (`Decimal(14,2)`), категория, дата (`date`) и
  необязательный комментарий.
- **Переводы** между счетами (`transfer` + `transfer_account_id`) — это не
  расход: они не попадают в расходы и не учитываются в бюджетах.
- Баланс счёта меняется в одной транзакции БД вместе с записью транзакции;
  удаление транзакции и перевод возвращают баланс обратно.

## Свои категории

Каталог категорий состоит из **системных** (засеяны миграцией: еда, транспорт,
жильё, развлечения, здоровье, подписки, покупки, связь, прочее, зарплата, прочий
доход) и **своих** — с иконкой, цветом и типом. Системные категории
редактировать нельзя (`403 system_category`), свои — можно создавать, править и
удалять.

## Быстрый ввод текстом

Строка быстрого ввода разбирается функциями `parseQuickTransaction` и
`guessCategoryName` из `@puls/shared`:

| Ввод | Результат |
| --- | --- |
| `обед 450` | расход 450, категория «Еда» |
| `зарплата +80000` | доход 80 000, категория «Зарплата» |

## Бюджеты на месяц

Бюджет задаётся на месяц по категории — пара `(user_id, category_id, month)`
уникальна, лимит хранится как `Decimal(14,2)`. Экран `/finance` показывает
прогресс-бар бюджета и остаток. Уровень бюджета (`budgetLevel` из
`@puls/shared`):

| Уровень | Условие |
| --- | --- |
| `ok` | потрачено меньше 80% лимита |
| `warning` | от 80% до 100% |
| `exceeded` | 100% и больше |

Остаток бюджета выводится и на дашборде дня (см. [Статистика и рекомендации](./stats-insights)).

## Регулярные платежи

Для аренды, подписок и других периодических списаний есть модель
`RecurringPayment`: название, сумма (`Decimal(14,2)`), тип
(`expense` / `income`), категория, счёт, периодичность (`weekly` / `monthly` /
`yearly`) и день расписания.

- День: для `weekly` — 1–7 (Пн–Вс), для `monthly` / `yearly` — 1–31. Для
  `yearly` дополнительно задаётся месяц (`schedule_month`). Дата прижимается к
  концу месяца (31-е → 30/28/29, високосный февраль учитывается).
- Время списания (`time_of_day`, по умолчанию `10:00`) считается в часовом поясе
  пользователя, с корректной обработкой переходов на летнее/зимнее время.
- **Транзакция создаётся автоматически** в срок планировщиком `RecurringScheduler`
  (тик раз в минуту; BullMQ/Valkey в продакшене, иначе таймер в процессе).
  Идемпотентность обеспечена условным `updateMany` по `next_run_at`, поэтому
  повторный тик и перезапуск не создают дубль.
- **Напоминание за 1 день** до списания уходит через `NotificationDispatcher`
  по правилу `payments` (через outbox в Telegram или Discord). Повторная отправка
  исключена полем `reminded_for`.
- Платеж можно **поставить на паузу и возобновить**; платежи на паузе
  игнорируются планировщиком.

Секция «Регулярные платежи» на `/finance` показывает список, ближайшие списания,
форму создания, паузу/возобновление и удаление.

## Мультивалютность и курсы

У счёта своя валюта (`RUB` / `USD` / `EUR`). У транзакции фиксируется:

- `rate` — курс валюты операции к основной валюте пользователя на дату операции;
- `amount_base` — сумма в основной валюте (`amount × rate`);
- `to_amount` — сумма зачисления при переводе между счетами разных валют.

Итоги статистики, бюджеты и дашборд считаются в основной валюте через
`amount_base`. Существующие строки мигрированы как `rate = 1`,
`amount_base = amount` (за́дним числом ничего не пересчитывается).

Курсы вводятся вручную через `/finance/rates` (таблица `ExchangeRate`,
уникальность `(user_id, date, base, quote)`, `source = manual`). Опционально
включается публичный источник без ключа (frankfurter.dev, данные ECB) —
переменными окружения:

| Переменная | Значение | Назначение |
| --- | --- | --- |
| `RATES_PROVIDER` | пусто / `frankfurter` | `frankfurter` включает подтягивание курсов с публичного API |
| `RATES_API_URL` | по умолчанию `https://api.frankfurter.dev/v1` | своё ECB-совместимое зеркало |

Если ручного курса нет, а провайдер включён, недостающий курс подтягивается и
кешируется (`source = provider`). Если курса нет нигде — операция отклоняется с
`400 rate_not_found`. Валюта транзакции, отличная от валюты счёта, отклоняется с
`currency_mismatch`.

В интерфейсе: форма счёта — выбор валюты; шторка быстрого ввода сужает список
счетов до счетов выбранной валюты; для операций в чужой валюте в списке
транзакций показан эквивалент в основной валюте (`≈ … в RUB`).

## API

Все маршруты — под `SessionGuard`, данные только текущего пользователя
(`/api/finance`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/overview?month=YYYY-MM` | Сводка для экрана: счета, категории, транзакции, бюджеты |
| GET / POST | `/categories` | Список / создание своей категории |
| PUT / DELETE | `/categories/:id` | Правка / удаление своей категории |
| GET / POST | `/accounts` | Счета и общий баланс / создание счёта |
| PUT / DELETE | `/accounts/:id` | Правка / удаление счёта |
| GET | `/transactions?from&to&accountId&categoryId&type&limit` | Список с фильтрами |
| POST | `/transactions` | Доход или расход |
| POST | `/transactions/quick` | Быстрый ввод: «обед 450», «зарплата +80000» |
| DELETE | `/transactions/:id` | Удаление с возвратом баланса |
| POST | `/transfers` | Перевод между счетами (не расход) |
| GET / PUT | `/budgets?month=YYYY-MM` | Бюджеты с потраченным и уровнем |
| PUT / DELETE | `/budgets/:id` | Правка / удаление бюджета |
| GET | `/recurring-payments` | Список (активные сверху, по дате) |
| GET | `/recurring-payments/upcoming` | Ближайшие списания |
| POST | `/recurring-payments` | Создать регулярный платёж |
| PUT | `/recurring-payments/:id` | Правка (пересчитывает `next_run_at`) |
| PUT | `/recurring-payments/:id/active` | Пауза / возобновление |
| DELETE | `/recurring-payments/:id` | Удалить |
| GET | `/rates?date&base&quote` | Курсы пользователя с фильтрами |
| PUT | `/rates` | Создать / обновить ручной курс |
| DELETE | `/rates/:id` | Удалить свой курс |

Ошибки — в едином формате `{ code, message }`: `validation_error`,
`account_not_found`, `category_not_found`, `transaction_not_found`,
`budget_not_found`, `system_category`, `no_account`, `rate_not_found`,
`currency_mismatch`, `unauthorized`.

## Изоляция данных

Каждый запрос фильтруется по `user_id` текущей сессии: чужой счёт, категория,
транзакция или бюджет не видны (`404`). Это закреплено интеграционным тестом
«Изоляция данных между пользователями».
