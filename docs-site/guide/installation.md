# Установка за 15 минут

«Пульс» — self-hosted сервис: вы разворачиваете его на своём сервере одной командой
Docker Compose и полностью контролируете данные. Ниже — кратчайший путь от пустого
сервера до работающего экземпляра с HTTPS.

## Автоматическая установка

Для чистого Debian/Ubuntu (VM, VPS, Proxmox LXC) есть установщик одной командой. Он ставит
Docker, клонирует репозиторий в `/opt/puls`, генерирует `.env` с секретами, собирает стек,
дожидается готовности и создаёт первого администратора (пароль — в `/root/puls-credentials.txt`).

**С доменом и HTTPS** (Let's Encrypt через Caddy; оба DNS-имени должны вести на сервер, порты 80/443 открыты):

```bash
curl -fsSL https://raw.githubusercontent.com/g99see/pulse-selfhosted/master/scripts/install.sh \
  | sudo bash -s -- --domain puls.example.com --sandbox-domain usercontent.example.com --email me@example.com
```

**Без домена, по http в локальной сети** (сайт на `http://<IP>`, песочница на порту 8080):

```bash
curl -fsSL https://raw.githubusercontent.com/g99see/pulse-selfhosted/master/scripts/install.sh \
  | sudo bash -s -- --http
```

Адрес сервера определяется автоматически, либо задайте `--host 192.168.1.50`. Без опций режима
в интерактивном терминале установщик спросит, что нужно. Полезные опции: `--dir`, `--branch`,
`--admin-email`, `--admin-nickname`, `--no-admin`, `--smtp-url`, `--registration open|invite|closed`,
`-y`, `--dry-run` (показать план). `--help` — полный список. Повторный запуск безопасен:
код обновляется, существующий `.env` не изменяется.

::: tip Proxmox LXC
Для Docker в непривилегированном контейнере включите в настройках LXC
**Options → Features: `nesting=1,keyctl=1`** и выделите минимум 2 ГБ RAM (или swap) — сборка
образов требует около 2 ГБ.
:::

::: warning Без SMTP
Если SMTP не задан, письма подтверждения не отправляются, и новые пользователи не смогут
подтвердить email. Поэтому установщик переводит регистрацию в режим «по приглашениям»
(`--registration open` отменяет это). Администратор создаётся уже с подтверждённым email.
Позже задайте `SMTP_URL` в `.env` и выполните `docker compose up -d api`.
:::

Обновление: `cd /opt/puls && sudo bash scripts/upgrade.sh` (делает бэкап, `git pull --ff-only`,
пересборку). Бэкапы лежат в `/opt/puls/backups`. Логи: `docker compose logs -f api web caddy`.
Ручная установка по шагам описана ниже.

## Требования

- **Docker с плагином Compose** (команда `docker compose`).
- **git** — чтобы получить код.
- Два DNS-имени, указывающих на сервер (см. «Домены» ниже).
- Порты **80** и **443** свободны (или их можно переопределить).

Node.js и pnpm для установки **не нужны**: API и web собираются внутри контейнеров.

::: tip
Сервер на 2 ГБ RAM справляется с чистой установкой; для небольшого сообщества
ориентир — 2 vCPU, 2–4 ГБ RAM, 20 ГБ диска. Одному пользователю достаточно
Raspberry Pi 4.
:::

## Шаг 1. Код

```bash
git clone <адрес-репозитория> puls
cd puls
```

## Шаг 2. Минимальный .env

```bash
cp .env.example .env
```

Для запуска достаточно задать четыре значения — остальное работает по умолчанию:

```bash
# .env
POSTGRES_PASSWORD=надёжный-пароль         # пароль БД
DOMAIN=example.com                        # основной домен
SANDBOX_DOMAIN=usercontent.example.com    # отдельный домен песочницы
ACME_EMAIL=admin@example.com              # контакт для Let's Encrypt
```

Полный разбор всех переменных — на странице [Настройка (.env)](/guide/configuration).

## Шаг 3. Домены и DNS

Нужны **два DNS-имени**, оба с A/AAAA-записями на адрес сервера:

| Домен | Переменная | Зачем |
| --- | --- | --- |
| Основной домен | `DOMAIN` | сам сервис, API и публичные профили |
| Домен песочницы | `SANDBOX_DOMAIN` | изолированная выдача пользовательского HTML |

::: warning
`sandbox_domain` — это **отдельный домен**, а не поддомен с общими cookie:
так пользовательский HTML не получает доступ к cookie и данным основного сайта.
Caddy режет cookie в обе стороны между доменами.
:::

Убедитесь, что на сервер проброшены порты **80 и 443**. Если они уже заняты
(например, Tailscale serve или другим reverse-proxy), задайте:

```bash
CADDY_BIND=127.0.0.1   # публиковать только на loopback
# либо сменить внешние порты:
HTTP_PORT=8080
HTTPS_PORT=8443
```

## Шаг 4. Запуск

```bash
docker compose up -d
```

Поднимаются сервисы `postgres`, `valkey`, `api`, `web`, `caddy` и `backup`. Порядок
запуска и готовность контейнеров Compose обеспечивает сам — см. следующий раздел.

## HTTPS

Caddy автоматически получает сертификаты **Let's Encrypt** для `$DOMAIN` и
`$SANDBOX_DOMAIN` (нужен корректный DNS и свободные 80/443). После первого запуска
проверьте на сервере:

```bash
curl -sk https://localhost/health
```

Локально (`DOMAIN=localhost`) Caddy отвечает редиректом 308 на HTTPS.

## Порядок запуска и healthchecks

Зависимости заданы в `docker-compose.yml`, поэтому Compose стартует сервисы каскадом:

```
postgres (healthy) ┐
                   ├─► api (healthy) ─► web (healthy) ─► caddy
valkey   (healthy) ┘                  └──────────────────┘
backup ── зависит от postgres (healthy)
```

- `postgres` и `valkey` проходят встроенные healthcheck-и;
- `api` ждёт обе БД, а при старте **сам применяет миграции Prisma** (`prisma migrate deploy`);
- `web` ждёт готовности `api`;
- `caddy` ждёт `api` и `web`.

## Мастер первого запуска

Откройте сайт в браузере (`http://localhost` или `https://$DOMAIN`). Пока в базе нет
ни одного пользователя, клиент переводит на страницу **`/setup`**.

1. Мастер создаёт первого пользователя с ролью `admin`. Email сразу считается
   подтверждённым — на пустом инстансе без SMTP иначе мастер заблокировал бы сам себя.
2. **После создания администратора мастер закрывается навсегда**: повторный вызов
   отвечает `409 setup_completed`.
3. Затем проходится **онбординг из 4 шагов**: валюта и часовой пояс, цели
   (деньги, здоровье, привычки), расписание уведомлений, приватность профиля.

## Проверка бэкап-сервиса

Сервис `backup` снимает дамп сразу при старте, затем раз в `BACKUP_INTERVAL_HOURS`
(по умолчанию 24 часа):

```bash
docker compose ps backup   # состояние: healthy
ls backups/                # первый архив backup-<UTC>.tar.gz появится сразу
```

Healthcheck сервиса следит за свежестью последнего успешного бэкапа (маркер
`.last-success`).

## Обновление

```bash
scripts/upgrade.sh
```

Скрипт выполняет три шага: **резервная копия → `docker compose pull` / `build` →  `docker compose up -d`**.
Миграции Prisma применяются контейнером `api` при старте. Пропустить бэкап можно
только явно (`SKIP_BACKUP=1`), и это не рекомендуется.

Восстановление одной командой (со сверкой версии схемы):

```bash
scripts/restore.sh backups/backup-<UTC>.tar.gz
```

## Установка на Raspberry Pi / домашний сервер

Особых требований к железу нет — тот же `docker compose up -d` работает и на ARM.

| Сценарий | Ориентир по ресурсам |
| --- | --- |
| Один пользователь | Raspberry Pi 4 |
| Небольшое сообщество | 2 vCPU, 2–4 ГБ RAM, 20 ГБ диска |

Домашнему серверу понадобится либо «белый» IP и проброс 80/443, либо использование
`CADDY_BIND`/`HTTP_PORT`/`HTTPS_PORT` за существующим reverse-proxy.
