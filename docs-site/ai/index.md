# AI-помощник

**AI-помощник** отвечает на вопросы о ваших собственных данных обычным языком:
одним сообщением вместо ручных фильтров и графиков. Он не является обязательной
частью «Пульса»: без подключённого API-ключа AI-функции полностью скрыты, а
рекомендации по правилам (обычные инсайты и разборы, см.
[Статистика и рекомендации](/guide/usage/stats-insights)) работают как обычно.

Технические описания блоков: `docs/PHASE4-AI-BACKEND.md` (backend),
`docs/PHASE4-AI-ASSISTANT.md` (чат и инструменты), `docs/PHASE4-AI-UI.md`
(интерфейс).

## Что умеет помощник

- **Чат о своих данных.** Вопросы вроде «Сколько я потратил на кафе в сентябре?»
  или «Когда у меня было лучшее настроение?». Модель получает данные через
  инструменты (**function calling**) — **только на чтение** и **только текущего
  пользователя**. Цикл ограничен 5 итерациями, затем выдаётся финальный ответ без
  инструментов. Никаких чужих данных и никаких операций записи напрямую.
- **Действия по подтверждению.** Помощник может *предложить* бюджет, цель или
  напоминание (`propose_budget`, `propose_goal`, `propose_reminder`), но
  сохраняет их лишь после того, как вы нажмёте **«Применить»**. Отклонённое
  предложение ничего не меняет; повторное «Применить» идемпотентно — сущность не
  дублируется.
- **Разборы недели и месяца.** Краткое резюме по финансам и самочувствию в
  дополнение к разбору по правилам. Перед отправкой видно, **что именно уйдёт
  провайдеру**.

## Инструменты (function calling)

Чтение: `get_spending_summary`, `list_transactions`, `get_mood`, `get_goals`,
`get_budgets`, `get_achievements`. Предложения: `propose_budget`, `propose_goal`,
`propose_reminder` — они лишь создают черновик, ничего не сохраняя.

`userId` берётся **только из сессии**; аргументы модели не могут выбрать другого
пользователя. Заметки чек-инов и имя пользователя в чат-инструменты не попадают.

## Уровни ключа

- **Общий ключ экземпляра** — его задаёт администратор в админке. С ним AI-помощник
  доступен всем пользователям, но с **лимитом токенов на пользователя в месяц**,
  который тоже настраивает администратор.
- **Личный ключ пользователя** — у каждого свой; имеет **приоритет** над общим
  ключом экземпляра. Если ключа нет нигде — AI выключен (`source: 'none'`).

## Провайдеры

Адаптеры за единым интерфейсом; поддерживаются:

| Провайдер | Базовый адрес по умолчанию | Модель по умолчанию |
| --- | --- | --- |
| `anthropic` | `https://api.anthropic.com` | `claude-3-5-haiku-latest` |
| `openai` | `https://api.openai.com/v1` | `gpt-4o-mini` |
| `openrouter` | `https://openrouter.ai/api/v1` | `openai/gpt-4o-mini` |
| `openai_compatible` | задаётся вами (`baseUrl`) | `llama3.1` |

`openai_compatible` покрывает свой endpoint, прокси и локальные модели (Ollama,
LM Studio). Поддерживается tool calling: у Anthropic — `tool_use`/`tool_result`,
у OpenAI-совместимых — `tool_calls`/role `tool`.

## Хранение ключа

::: info Ключ никогда не попадает в браузер
Ключ хранится **в базе данных зашифрованным** (`AES-256-GCM`, формат
`v1.<iv>.<tag>.<ciphertext>`). Мастер-ключ шифрования задаётся переменной
окружения `APP_ENCRYPTION_KEY`. Расшифрованный ключ используется только на сервере,
не отдаётся в браузер и не пишется в логи. В выгрузку данных ключ не попадает.
:::

Если мастер-ключ недоступен (production без `APP_ENCRYPTION_KEY`), запись ключа
отвечает `503 ai_key_storage_unavailable`.

В интерфейсе ключ показан только **последними 4 символами**, рядом — кнопка
**«Проверить подключение»**, которая делает тестовый запрос к провайдеру и
показывает результат. Пустое поле ключа при сохранении оставляет прежний ключ.

## Приватность: что уходит провайдеру

Наружу уходит только то, что нужно для ответа: текст вашего вопроса и те данные,
которые запросили инструменты. **Имя и email провайдеру не отправляются.**

Перед разбором недели или месяца **видно, какие именно данные будут отправлены**
(эндпоинт предпросмотра отдаёт ровно тот текст, что уйдёт провайдеру, и пометку
`isLocal`). Заметки и имя попадают в отправку **только если вы поставите отдельную
галочку** (`includeNotes` / `includeName`, по умолчанию выключены).

## Рамки (system prompt)

Системный промпт (`AI_SYSTEM_PROMPT`) задаёт ограничения: помощник **не ставит
медицинских диагнозов** и **не даёт советов по конкретным инвестициям**. При
тревожном сигнале (свежий инсайт `wellbeing_concern` или серия очень низкого
настроения) в ответ добавляется блок поддержки с контактами служб.

## Учёт расхода

Расход по каждому пользователю — токены (`tokens_in`, `tokens_out`) и примерная
**стоимость** в USD — виден в админке, с разбивкой по месяцам (см. [Администрирование](/admin/)).
Для общего ключа месячный лимит проверяется перед каждым запросом; при его
достижении возвращается `ai_limit_reached` (429).

## Локально: Ollama и LM Studio

Чтобы данные вообще не покидали ваш сервер, в качестве провайдера можно указать
локальную модель. Ollama и LM Studio предоставляют OpenAI-совместимый адрес, поэтому
настраиваются как провайдер `openai_compatible`.

::: warning Ollama на хосте, «Пульс» в Docker
Если Ollama работает на самом хосте, а «Пульс» — в контейнерах, контейнеру нужен
сетевой доступ к хосту. Один из способов — добавить сервису в `docker-compose.yml`
запись `extra_hosts` с `host.docker.internal:<ip хоста>` и указать этот адрес как
endpoint провайдера. Так контейнер дотягивается до Ollama, слушающего на хосте.
:::

## Как подключить ключ

1. Убедитесь, что в `.env` задан `APP_ENCRYPTION_KEY` — иначе зашифрованные ключи
   сохранить нельзя. Подробнее: [Настройка (.env)](/guide/configuration).
2. Откройте настройки AI в кабинете (для общего ключа — в админке, `/admin/ai`).
3. Выберите провайдера и адрес; для локальных моделей — OpenAI-совместимый endpoint
   Ollama или LM Studio.
4. Вставьте ключ и нажмите **«Проверить подключение»**.
5. Сохраните. После этого пункт AI появится в интерфейсе.

::: warning Проверьте безопасность
Для облачных провайдеров помните: вопросы и выбранные данные уходят на их серверы.
Если это нежелательно — используйте локальную модель (Ollama или LM Studio).
:::

## API

Пользовательские маршруты — под `SessionGuard`, префикс `/api/ai`:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/ai/status` | Статус: включён ли AI, провайдер, модель, расход за месяц |
| PUT | `/api/ai/key` | Сохранить личный ключ (провайдер, `baseUrl`, модель) |
| DELETE | `/api/ai/key` | Удалить личный ключ (возврат к общему) |
| POST | `/api/ai/key/test` | Проверить текущий ключ |
| POST | `/api/ai/chat` | Чат: `{ message, history? }` → `{ reply, proposals, usage }` |
| POST | `/api/ai/proposals/:id/apply` | «Применить» предложение |
| POST | `/api/ai/review/preview` | Предпросмотр разбора: `{ period, includeNotes?, includeName? }` |
| POST | `/api/ai/review` | Получить разбор недели/месяца |

Админские маршруты (`@Roles('admin')`, префикс `/api/admin/ai`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/admin/ai/settings` | Общий ключ, провайдер, модель, лимит токенов |
| PUT | `/api/admin/ai/settings` | Сохранить настройки (пустой `apiKey` оставляет прежний; `null` очищает поле) |
| POST | `/api/admin/ai/settings/test` | Проверить подключение до сохранения |
| GET | `/api/admin/ai/usage?month=YYYY-MM` | Расход по пользователям (без `month` — текущий месяц) |

Ошибки — в едином формате `{ code, message }`: `ai_not_configured` (409),
`ai_limit_reached` (429 для общего ключа), `ai_provider_error` (502, с полем
`reason`; тела ответов провайдера не логируются и не пробрасываются),
`ai_proposal_not_found` (404), `ai_proposal_invalid_payload` (400),
`validation_error` (400), `unauthorized` (401). Классификация ошибок провайдера:
401/403 → `invalid_key`, 404 → `model_not_found`, 429 → `limit_reached`,
сеть → `unreachable`, иначе `unknown`.
